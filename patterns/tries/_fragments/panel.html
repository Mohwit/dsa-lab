1. Words as paths of letters

You have a list of words. Someone types a few letters. You want every word that starts with them.

The slow way reads every word in the list, every time. The trie way stores the words as a tree of letters. You walk down one letter per keystroke, and everything below you is a match.

Analogy: your phone's autocomplete. Type "c" and the phone has already ruled out every word that does not start with c. Type "a", then "r": each letter takes one step down a path, and the suggestions are whatever hangs below that point. The phone never re-reads its whole dictionary for each key you press.

The dictionary on this page: cat, car, card, care, cart, dog, dot, door, deer, can. The question: which words start with car?

Before you press play: how many letter comparisons does reading every word cost? (Stop reading a word at its first letter that differs.)

22 comparisons. Each c-word costs 3 (cat and can fail on the third letter, the four car-words pass all three). Each d-word fails at once: 1 each. 6 x 3 + 4 x 1 = 22.

Trie: walk, then collect. Walk c, a, r (3 steps), then visit the 3 nodes hanging below r. Blue fill marks the end of a word.

Slow: read every word. Compare each word with "car" letter by letter, stopping at the first mismatch. All 10 words, every time.

3. Mental map: from a blank page to working code

  1. SignalThe word "prefix" or "starts with". Many words checked at once. Autocomplete or suggestions. A wildcard letter. "Find all dictionary words in this grid".
  2. Ask"Am I asking many prefix questions about one fixed set of words?" If you only ask "is this exact word here?", a set is simpler and just as fast.
  3. Pick the variantFour shapes:
    • insert, search, starts withThe plain trie: a walk down one letter at a time.
    • "." matches any letterWildcard search: DFS that tries every child at a dot.
    • many words hidden in a gridTrie plus grid DFS: walk the board and the trie together, stop when no word continues.
    • "how many start with", "top 3 suggestions"Store a count or a short list on each node as you insert.
  4. InvariantEach node stands for exactly one prefix: the letters on the path from the root. A node exists if and only if some inserted word starts with that prefix.
  5. Steps1. A node class with children = {} and is_end = False. 2. Insert: walk, creating missing children, mark the end. 3. A shared _walk(s) that returns the node for s or None. 4. Search checks is_end; starts with only checks the node exists. 5. For more, add DFS below the node.
  6. CheckDid you set and check is_end? Does search avoid creating nodes? Is children created fresh in __init__, not as a default argument? At a wildcard, do you try every child before giving up?

Template D: many words in a grid (Word Search II)

Searching the grid once per word repeats the same work. Put all the words in a trie, then run one DFS from each cell that walks the grid and the trie together.

Rule to rememberSearch asks "is there a word ending here?"; starts with asks "is there a path here?". Keep them apart with is_end, and let one shared walk do the stepping.
Pattern words

5. Spot the pattern: does a trie help?

A. A search box shows the three alphabetically first product names that start with what the user typed, after every key press.

Yes, plain trie (plus a stored short list). Signal: prefix after every key. Walk one letter per key press, and keep the best three words on each node. Sorting plus binary search also works here.

B. A word game lets players type patterns like "b..k". Answer whether any dictionary word matches, many times a second.

Yes, wildcard search. A dot means "try every child". Words of the wrong length or wrong fixed letters are skipped as whole branches.

C. Given a letter board and 3000 words, list every word you can trace through neighbouring cells.

Yes, trie plus grid DFS. One board walk checks all 3000 words at once, and stops as soon as the letters so far start no word.

D. Replace each word in a sentence by its shortest root from a list (for example "cattle" becomes "cat" if "cat" is a root).

Yes, plain trie. Put the roots in a trie. Walk each word and stop at the first node with is_end. That is Replace Words.

E. A spell checker answers one question: is this exact word in the dictionary?

Not needed. No prefixes, no wildcards: a Python set answers exact lookups in O(L) time (hashing the word) with much less code. Reach for a trie only when the question is about starts.

F. Find the longest stretch of letters that two long strings share, in the same order with no gaps.

Not this pattern. It sounds like prefixes, but it compares two strings at every pair of positions. That is 2D dynamic programming (a grid of match lengths).

Trigger signals"Prefix", "starts with", autocomplete, wildcard letters, many words searched at once (often in a grid). One exact lookup is a set, not a trie.

6. Four classic traps

Trap 1: no end-of-word mark 
def search(self, word):
    return self._walk(word) is not None     # this is starts_with, not search

# measure.py, only 'card' inserted:
search('car') without the end check: True     # wrong
search('car') with it:               False

Fix: set node.is_end = True at the end of insert, and return node is not None and node.is_end in search.

Trap 2: a shared default dict 
class TrieNode:
    def __init__(self, children={}):   # made once, shared by every node
        self.children = children

# measure.py: insert 'ab', then search('b'):
True     # root.children holds both 'a' and 'b'

Fix: Python builds a default value once, when the function is defined. Write self.children = {} inside __init__.

Trap 3: a search that builds nodes 
node = node.children.setdefault(ch, TrieNode())   # inside search

# measure.py, trie holds 'car':
search('cab') = False, nodes 3 -> 4, starts_with('cab') now = True   # wrong

Fix: only insert creates nodes. Lookups return as soon as a letter is missing.

Trap 4: giving up after the first branch 
for child in node.children.values():
    return dfs(child, i + 1)        # returns the first child's answer, even False

# measure.py, words cat and dog, pattern '.og':
buggy False    fixed True

Fix: if dfs(child, i + 1): return True inside the loop, and return False after it.

Maths

7. Complexity: letters, not words

Step 1: insert, search and starts with cost the word's length

Each operation does one dict lookup per letter. For a word of length L that is O(L), whether the trie holds 10 words or 10 million.

The race in section 1: the trie took 3 walk steps for bad at every size; only the collect part grew with the number of matches (2, 5, 27).

Step 2: memory is at most the total letters, often much less

Each inserted letter creates at most one node. Shared starts create none.

10 lesson words: 35 letters, 17 nodes
10000 random words: 44,885 letters, 11,091 nodes

A set of every prefix would also hold 11,091 strings, but it stores 53,155 letters, and each lookup must hash the whole prefix. The trie stores one letter per node and reuses the walk. Space is O(total letters); a node with a 26-slot array instead of a dict costs 26 slots per node.

Step 3: wildcards branch

A dot tries every child, so a pattern with d dots can visit up to 26d paths in the worst case. In practice it stops at the first match: on the 10,000 random words, ... found a word after 4 calls and ...... after 7 (measure.py). The worst case is a pattern that almost matches everywhere and fails at the last letter.

Check yourself

9. Your lesson's questions

Q1. Insert app, apple, apply, apt into an empty trie. How many nodes are created (not counting the root)?

7 nodes for 16 letters: a, p, p, l, e, y, t. The words share "ap", and apple and apply share "appl". measure.py prints 7 and 16.

Q2. Only "apple" is stored. What do search("app") and starts_with("app") return?

False and True. The path exists, but no word ends at the second p. This is exactly the case the end-of-word mark is for.

Q3. The trie holds cat, cot, cut, cup, dog. Why does the pattern "..g" need 8 calls when "c.t" needs 4?

The first dot tries c first. Under c, the second dot tries a, o and u, and none has a g child: 3 dead ends. Only then does it back out and try d, o, g. Calls: root, c, a, o, u, d, o, g = 8. "c.t" finds cat on its first branch: root, c, a, t = 4.

Glossary: new words from this lesson

trie (prefix tree)
A tree whose edges are letters; each node stands for one prefix.
prefix
The first few letters of a word.
root
The top node, standing for the empty prefix.
children
A dict from the next letter to the next node.
end-of-word mark
The is_end flag: a whole word stops at this node.
wildcard
A pattern letter that matches any one letter; in a trie, try every child.
DFS
Follow one path all the way down, then back up and try the next.
pruning
Stopping a search branch early because it cannot lead to an answer.

Recap: the pattern card in one minute

Idea: store words as paths of letters. Words with the same start share a path, so a prefix question is one walk down.

Signals: prefix, starts with, autocomplete, wildcard letters, many words searched at once (often in a grid). One exact lookup is a set.

Template: children = {}, is_end = False; insert walks and creates; a shared _walk; search checks is_end, starts with does not; wildcard DFS tries every child at a dot.

Cost: O(L) per operation, O(total letters) memory. On 10,000 words: 30 trie steps against 11,374 scan comparisons for "bad".

Traps: no end mark; a shared default dict; search that creates nodes; returning after the first wildcard branch.
