1. When one number is not enough, use a table

In 1D DP, one number named each smaller question: "ways to reach step i". Some problems need two numbers. A robot on a grid needs a row and a column. Comparing two words needs a position in each word.

Two numbers make a table. Each cell is one smaller question. You fill the cells in an order where every cell's sources are already done.

Analogy: a delivery map of city blocks. A courier starts at the top-left corner and may only ride right or down. On every corner of the map, write how many routes reach it. Corners on the top street and the left avenue have just 1 route (go straight). Any other corner is reached from the corner above or the corner to the left, so its number is those two added. Fill the map row by row and the bottom-right corner holds the answer.

Try it: the same 3 x 4 map, two ways

How many right-or-down routes go from the top-left to the bottom-right of a 3 row, 4 column grid?

Slow: plain recursion. Each cell counts how many times the recursion visits it. Watch the same cells get asked again and again.

Fast: fill the map. Each new cell (teal) adds the cell above and the cell to the left (blue). Each cell is filled once.

Rule to rememberSame recipe as 1D DP, with two numbers in the state: dp[r][c] or dp[i][j]. Draw the table first; the code is just the drawing.

Why the calls are 2 x routes - 1

Every route ends at a base cell on the top row or left column, and each call there returns 1. So the recursion has exactly one leaf call per route. Each other call makes two calls, so the tree has one fewer inner call than leaves:

calls = routes + (routes - 1) = 2 x routes - 1

The number of routes is "choose which of the (rows - 1) + (cols - 1) moves go down": C(22, 11) = 705,432 on a 12 x 12 grid. That grows exponentially. The table has rows x cols cells: 144.

4. Mental map: find the two numbers, then draw the table

  1. SignalA DP smell (count ways, min / max, true / false) plus one of: a grid, two strings or lists, a list and a budget, a range inside one string, or a "mode" that changes as you go.
  2. Ask"What two things change as I make choices?" Try to finish "dp[_][_] is the answer for ...". If one number would do, stay 1D.
  3. Pick the variantThe two numbers tell you the family.
    • a grid, moves right / downgrid paths: (row, col), sources above and left
    • two strings or liststwo prefixes: (i in a, j in b), sources above, left, diagonal
    • items and a budget or targetknapsack: (items used, amount left)
    • a range inside one string or rowinterval: (left, right), fill by length
    • days with a mode: holding, coolingstate machine: (day, mode), a few rolling numbers
    • a grid with moves in any directionnot plain DP: BFS, or DFS with memo when values strictly increase
  4. DrawRows = first number, columns = second. Add row 0 / column 0 for "empty" when the state is a prefix. Write the base row and column. Point arrows from each cell to its sources.
  5. InvariantA cell is filled only after all its source cells are final. The arrows decide the fill order: row by row, by length, or backwards.
  6. Write itTwo loops in the fill order, the transition inside, the answer in the corner (or the max over the table). Then ask: does each row read only the row above? If yes, keep one row.
  7. CheckIs the table (m + 1) x (n + 1) with the empty row? Does any cell read a cell not yet filled? With one row, does the loop direction reuse an item by mistake? For counting with coins, does the loop order count orders or combinations?

5. Templates: grid, two strings, budget, one row

Template A: grid paths

CodeWhat it means
def unique_paths(m, n):Routes on an m-row, n-column grid.
dp = [[1] * n for _ in range(m)]Start every cell at 1. The top row and left column keep it: one straight route. Build rows with a loop, never [[1] * n] * m (that copies one row m times).
for r in range(1, m):Rows top to bottom...
for c in range(1, n):... and columns left to right, so above and left are ready.
dp[r][c] = dp[r - 1][c] + dp[r][c - 1]Arrive from above or from the left.
return dp[m - 1][n - 1]The bottom-right corner.

Template B: two strings (longest common subsequence)

A longest common subsequence is the longest run of letters that appears in both words in the same order, gaps allowed. "stone" and "tones" share "tone".

CodeWhat it means
m, n = len(a), len(b)Lengths of the two words.
dp = [[0] * (n + 1) for _ in range(m + 1)]dp[i][j] = LCS of a[:i] and b[:j]. The +1 adds the empty-prefix row and column, all 0.
for i in range(1, m + 1):One more letter of a each row.
for j in range(1, n + 1):One more letter of b each column.
if a[i - 1] == b[j - 1]:The last letters of both prefixes match. (Cell i stands for the letter at index i - 1.)
dp[i][j] = dp[i - 1][j - 1] + 1Use that letter: one more than both prefixes without it (the diagonal).
else:They differ: one of the two last letters is not used.
dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])Drop a's last letter (above) or b's (left), keep the better.
return dp[m][n]Both whole words.

Step through it. Row labels are letters of "stone", column labels are letters of "tones"; "" is the empty prefix.

25 cells computed, answer 4. The final table matches measure.py row by row.

Edit distance uses the same table with a different transition: the fewest single-letter inserts, deletes or replacements that turn a into b. Row 0 is j (insert j letters), column 0 is i (delete i letters). On a match, copy the diagonal. Otherwise take 1 + the smallest of: above (delete), left (insert), diagonal (replace).

if a[i - 1] == b[j - 1]:
    dp[i][j] = dp[i - 1][j - 1]
else:
    dp[i][j] = 1 + min(dp[i - 1][j], dp[i][j - 1], dp[i - 1][j - 1])
# edit("flaw", "lawn") = 2: delete f, insert n

Template C: position x budget (coin change II)

How many different combinations of coins worth 1, 2 and 3 make 4? Row i means "using only the first i coin types". Column a is the amount.

CodeWhat it means
dp[i][0] = 1 for every iOne way to make 0: take nothing.
c = coins[i - 1]The coin type this row adds.
dp[i][a] = dp[i - 1][a]Ways that do not use coin c at all: the row above.
if a >= c: dp[i][a] += dp[i][a - c]Ways that use c at least once: take one c, then any way to make a - c in this same row (c may be used again).

4 combinations: 1+1+1+1, 1+1+2, 2+2, 1+3. Reading the same row is what makes coins reusable; reading the row above would allow each coin once (0/1 knapsack).

Template D: shrink the table to one row

If a row reads only itself and the row above, one row is enough. Overwrite it in place:

CodeWhat it means
dp = [1] * nThe top row of the grid.
for _ in range(1, m):Each pass turns the row into the next row.
for c in range(1, n):Left to right.
dp[c] += dp[c - 1]Before the update, dp[c] still holds "above". dp[c - 1] is already the new "left".
return dp[-1]O(m x n) time, O(n) memory.
Rule to rememberWhen you shrink to one row, the loop direction decides what "old" and "new" mean. Left to right reads the new left value (items reusable). Right to left reads only old values (each item once). See trap 2.

The highlighted row is the most common in interviews. Once you see "two strings", the table nearly draws itself.

A state machine in three numbers

Buy and sell a share many times, but after a sale you must wait one day. Each day you are in one of three modes. Keep the best profit for each:

hold, sold, rest = float("-inf"), 0, 0
for p in prices:
    hold, sold, rest = max(hold, rest - p), hold + p, max(rest, sold)
return max(sold, rest)
# prices [3, 1, 4, 2, 5, 0, 3]: 6, and a brute force over every action list agrees

The table is days x 3 modes, but each day reads only yesterday, so three rolling numbers are enough. The moves: hold (keep holding, or buy after resting), sold (sell what you hold), rest (wait, which ends any cooldown).

Grid with arrows in all directions

If moves can go up, down, left and right, there is no row-by-row order. Longest Increasing Path still works with memoised DFS, because each step must climb to a bigger value, so no path loops back. Without that "always increasing" rule you need BFS or a graph algorithm instead.

Pattern words

7. Spot the pattern: 2D DP, and which two numbers?

A. A spell checker suggests the dictionary word that needs the fewest letter changes (add, remove or swap one letter) to become what you typed.

Yes, two strings. Edit distance between the typed word and each candidate: dp[i][j] over prefixes of both.

B. A hiker packs items, each with a weight and a joy score, and the bag holds at most 15 kg. Each item can be packed once. Maximise total joy.

Yes, 0/1 knapsack. dp[i][w] = most joy from the first i items within weight w. One row works if you loop w backwards.

C. A robot in a maze can step up, down, left or right. Find the fewest steps to the exit.

No, this is BFS. It looks like a grid DP, but moves go in every direction, so a cell's answer can depend on cells that depend on it. No fill order exists. Fewest steps on an unweighted grid means BFS (graphs lesson).

D. Two recipe step lists must be merged into one schedule that keeps each recipe's order. Can a given schedule be such a merge?

Yes, two strings. dp[i][j] = can the first i + j steps of the schedule be made from i steps of the first recipe and j of the second. This is Interleaving String.

E. Climb a staircase with steps of 1 or 2; each step has a cost. Find the cheapest way to the top.

DP, but 1D. Only one thing changes: which step you are on. A second number would add nothing. Do not reach for a table when a list will do.

F. Put + or - in front of each number in a list so the total hits a target. How many ways?

Yes, knapsack. dp[i][s] = ways to reach sum s with the first i numbers. Sums can be negative, so shift them or use a dict per row. This is Target Sum.

Trigger signalsTwo strings, a grid with one-way moves, items with a budget, a range [i, j], or a day plus a mode. Not 2D DP: moves in every direction (BFS), or only one thing changing (1D).

8. Four classic traps

Trap 1: reading a cell that is not filled yet

Counting palindromic substrings with pal[i][j] = s[i] == s[j] and pal[i + 1][j - 1]. The source is in row i + 1, the row below. Loop i upward from 0 and that row is still all False:

for i in range(n):                  # wrong: row i + 1 not filled yet
# == 9. Trap: interval fill order, count palindromic substrings ==
'aaaa': right order (i from the end) = 10   wrong order (i from 0) = 7

Fix: follow the arrows. Sources below mean for i in range(n - 1, -1, -1), or loop by length, shortest first.

Trap 2: one row, wrong direction

Subset sum ("can some items, each used once, add up to T?") in one row. Looping the target upward lets an item read a cell it just updated, so it gets used twice:

for t in range(x, target + 1):       # wrong for 0/1
    dp[t] = dp[t] or dp[t - x]
forwards  = True   # nums [3], target 6: used the 3 twice
backwards = False

Fix: for "each item once", loop range(target, x - 1, -1). For "reuse allowed" (coin change), forwards is exactly right.

Trap 3: loop order counts orders instead of combinations

Coin change II with coins outside counts each mix once. Put the amount loop outside and 1 + 2 and 2 + 1 count as two:

# == 7. Trap: loop order in coin change II, coins [1, 2], amount 3 ==
coins outer (combinations) = 2
amount outer (orders)      = 3

Fix: decide whether order matters. Combinations: coins outer. Orders (like the stairs, or Combination Sum IV): amount outer.

Trap 4: no empty-prefix row, and Python wraps -1

Build the LCS table as m x n without row 0 and column 0. At i = 0, dp[i - 1] is dp[-1]: Python quietly reads the last row. No error, just a wrong answer:

dp = [[0] * n for _ in range(m)]      # wrong: no empty row
...  dp[i][j] = dp[i - 1][j - 1] + 1
smallest failing pair found: ('a', 'aa') -> 2 instead of 1

With one row, dp[-1] is row 0 itself, which already holds the 1 from the first match, so the second "a" counts it again. Fix: size the table (m + 1) x (n + 1), let row 0 and column 0 mean "empty", and read letters with a[i - 1].

Rule to rememberDraw the arrows, then loop so every arrow points at a filled cell. Add the empty row. In one row, the direction is part of the meaning.
Maths

9. Complexity: cells x work per cell

Two strings of length 10, then 1000

Plain LCS recursion on two 10-letter words with no letter in common: 369,511 calls (2 x C(20, 10) - 1, the worst case). The table: 11 x 11 = 121 cells.

For two 1000-letter strings: 1,002,001 cells, 1,000,000 of them computed, each in O(1). That is O(m x n) time: a million small steps, which Python handles. Memory O(m x n), or O(n) with a rolling row if you only need the number (not the actual subsequence).

Knapsack and the "pseudo-polynomial" catch

Coin change II and subset sum have (items + 1) x (budget + 1) cells: O(k x T). That depends on the value of the budget T, not on how many digits it has. A target of 109 makes the table far too big even with few items. Interviewers sometimes ask about this: it is called pseudo-polynomial.

Interval DP costs more

Palindromic substrings: n2 / 2 cells, O(1) each, so O(n2). Burst Balloons: n2 ranges, and each tries every last balloon in the range, so O(n3). Count the inner loop, not just the table.

Rule to rememberTime = number of cells x work per cell. Memory = the table, or one row when each row reads only the row above.

Glossary: new words from this lesson

2D state
A smaller question named by two numbers: dp[i][j].
dp table
The grid of stored answers, one cell per state.
prefix
The first i letters of a word; the empty prefix has i = 0.
empty-prefix row
Row 0 and column 0 for "nothing yet"; they hold the base cases.
source cells
The cells a transition reads; they must be filled first.
fill order
The visiting order that keeps every source filled before it is read.
longest common subsequence
The longest in-order (gaps allowed) run of letters found in both strings.
edit distance
The fewest single-letter inserts, deletes and replacements that turn one string into the other.
knapsack
Choosing items under a budget; 0/1 means each item at most once, unbounded means reuse allowed.
interval DP
The state is a range [i, j]; fill short ranges first.
state machine DP
A position plus a small mode (holding, cooling); each step moves between modes.
rolling row
Keep one row instead of the table when each row reads only the row above.
pseudo-polynomial
Cost that grows with a number's value (like a budget), not with the input's length.

Recap: the pattern card in one minute

Idea: when a smaller question needs two numbers to describe it, store the answers in a table and fill it so every cell's sources are ready.

Signals: two strings, a grid with one-way moves, items and a budget, a range [i, j], a day plus a mode.

Template: dp = [[0] * (n + 1) for _ in range(m + 1)]; base row and column; two loops in the fill order; the transition reads above / left / diagonal; answer in the corner.

Cost: cells x work per cell, usually O(m x n). Memory O(n) with one rolling row. A 12 x 12 grid: 1,410,863 plain calls against 144 cells.

Traps: reading unfilled cells (follow the arrows), one-row loop direction (backwards for each-item-once), loop order (combinations vs orders), the missing empty row (Python's -1 wraps silently).

In the sandbox, type two words and watch the LCS or edit distance table fill, with the plain recursion's call count beside it. Try a word against itself, and against the empty word.
