1. Write the answer on each step, then read it back

You climb a staircase. Each move takes you up 1 step or 2 steps. In how many different ways can you reach step n?

To stand on step 5, your last move came from step 4 or from step 3. So the ways to reach 5 are the ways to reach 4 plus the ways to reach 3. The big question is made of two smaller copies of itself.

Analogy: chalk on the stairs. Walk up from the bottom with a piece of chalk. On each step, write how many ways reach it. To fill a step, read the two numbers just below it and add them. You never climb back down to recount. Each number is worked out once and then only read.

That is the whole pattern. Dynamic programming (DP) means: find the smaller copies, store each answer once, and build up.

Try it: the same question, two ways

Both players answer "how many ways to reach step 5?". Step through them and watch the counters.

Slow: plain recursion. Each call asks its two smaller copies, which ask theirs. Faded nodes are calls still to come. Orange rings are calls whose answer was already worked out earlier.

Fast: the chalk table. Fill dp left to right. The blue cells are the two answers each new cell reads.

Both counts come from running the two methods (in the page and in measure.py, which prints 9 calls and 5 cells for n = 5). The answer is 8 either way. The gap looks small here. The next section shows how fast it grows.

Rule to rememberIf a problem's answer is built from answers to smaller copies of the same problem, and those smaller copies repeat, store them. That is DP.

These repeats have a name: overlapping subproblems. When you see them, DP turns exponential work into linear work.

Why the plain calls grow so fast

Let calls(n) be the number of calls for height n. One call for n itself, plus all the calls for n - 1 and for n - 2:

calls(n) = 1 + calls(n - 1) + calls(n - 2), calls(1) = calls(2) = 1

That is the same shape as the answer itself, so it grows like the answer: each step up multiplies the work by about 1.6. Ten more steps means about 120 times more calls (13,529 at n = 20 against 1,664,079 at n = 30). Big-O calls this O(1.6n), which is exponential.

With memory, each height is worked out once and asked at most twice: measure.py confirms 2n - 3 calls for every n from 3 to 39.

4. Mental map: from a blank page to a DP loop

Read this when a new problem smells like DP. The middle of it is the five-question recipe; answer all five before you write code.

  1. Signal"How many ways", "minimum cost", "maximum total", "can you reach", "longest ..." over a line of things. Choices at one spot change what is allowed later. A brute force would try every combination.
  2. Ask"If I knew the answer for every smaller prefix (or smaller amount), could I get the answer for this one with a simple rule?" If yes, it is DP.
  3. Pick the variantThe shape of the last choice tells you the transition.
    • "how many ways", fixed movescount ways: add the smaller answers (stairs, decode ways)
    • "cheapest" or "most"min / max cost: take the best of the options (min cost stairs)
    • "cannot take two neighbours"take or skip: max(skip, take + dp[i - 2]) (house robber)
    • "use any item again", a target amountunbounded choices: loop over items for each amount (coin change)
    • "subsequence" or "subarray ending here"ends at i: dp[i] = best that ends exactly at i, answer is max(dp) (LIS, max product)
    • "split the string into valid pieces"string partition: dp[i] = can the first i letters be split (word break, decode ways)
    • "can I pick a subset that sums to T"subset sum: a row of booleans over sums 0..T, loop sums backwards (partition equal subset sum)
  4. Recipe1. State: finish the sentence "dp[i] is ...". 2. Transition: how dp[i] comes from smaller cells. 3. Base cases: the cells you know outright. 4. Fill order: so every read cell is ready. 5. Answer: which cell (dp[n], or max over all).
  5. InvariantWhen you fill dp[i], every cell it reads is already final. Nothing is ever recomputed.
  6. Write itFirst the plain recursion with @cache (fastest to get right). Then turn it into a loop. Then keep only the cells you still read.
  7. CheckDoes the state sentence really cover the question? Is the base case right for the empty input (dp[0])? Does the order read only filled cells? Is the answer in dp[n] or in max(dp)? Could a greedy rule do it instead (then prove it, or stay with DP)?
Say it in an interview"Let dp[i] be ... . To get dp[i] I look at the last choice, which leaves me with ... . The base case is ... . I fill left to right and the answer is ... ." Those five sentences are most of a DP interview.

5. Three templates: top-down, bottom-up, two variables

Write them in this order. Each one is a small, safe change from the one before.

Template A: top-down with @cache

CodeWhat it means
from functools import cachePython's built-in notebook for function answers.
@cacheRemember every result by its arguments. A repeated call returns the stored answer at once.
def climb(n):The state: climb(n) = ways to reach step n.
if n <= 2:Base cases: 1 way to reach step 1, 2 ways to reach step 2.
return nStops the recursion.
return climb(n - 1) + climb(n - 2)The transition: the last move came from one step or two steps below.

Here is what @cache does for you, written out with a dict. Watch the memo fill and the call stack grow and shrink.

7 calls instead of 9 for n = 5 (the 2n - 3 rule), and the stack is 4 calls deep at its deepest. That depth is the hidden cost of top-down: about n frames.

Template B: bottom-up table

CodeWhat it means
def climb(n):Same question, no recursion.
if n <= 2: return nSmall inputs answer directly (and keep dp[2] below in range).
dp = [0] * (n + 1)One cell per step, 0 to n. Size n + 1 so dp[n] exists.
dp[1], dp[2] = 1, 2Write the base cases first.
for i in range(3, n + 1):Fill order: left to right, so i - 1 and i - 2 are ready.
dp[i] = dp[i - 1] + dp[i - 2]The same transition, now reading the table.
return dp[n]The answer lives in the last cell.

Template C: keep only what you read

CodeWhat it means
prev, cur = 1, 2dp[i - 2] and dp[i - 1]. Nothing older is ever read again.
for _ in range(3, n + 1):Same loop.
prev, cur = cur, prev + curSlide both forward one step. Python assigns both at once, so no temporary is needed.
return curO(n) time, O(1) memory.
Rule to rememberGet it right top-down, then make it a loop, then shrink it. In an interview, a correct @cache solution is already a strong answer; mention the loop and the O(1) version as follow-ups.

Play: rob the street (take or skip)

A robber cannot rob two houses side by side (the alarms are linked). Click houses to rob them. Can you match the best total? Neighbours of a picked house are blocked.

your loot0
best possible?

Both easy rules lose here: every other house gets 16, biggest first gets 16, and the best is 18 (houses worth 4, 7 and 7). measure.py prints all three. DP wins because at each house it keeps both futures alive: "I skipped this one" and "I took this one".

CodeWhat it means

Watch: coin change fills amounts 0 to 6

Coins worth 1, 3 and 4, any number of each. What is the fewest coins that make 6? Each amount tries every coin and reads the amount that coin leaves (blue).

dp ends as [0, 1, 2, 1, 1, 2, 2]: 6 needs 2 coins (3 + 3), after 13 coin tries. The same numbers come out of measure.py.

Ends at i: the longest rising subsequence

For [2, 5, 3, 7, 1, 8], let dp[i] be the longest rising run that ends exactly at index i. Each i looks back at every smaller earlier number:

dp = [1] * len(nums)
for i in range(len(nums)):
    for j in range(i):
        if nums[j] < nums[i]:
            dp[i] = max(dp[i], dp[j] + 1)
return max(dp)
# dp = [1, 2, 2, 3, 1, 4]: answer 4, after 15 comparisons

"Ends at i" states are the trick for subsequences and subarrays: the best run could end anywhere, so the answer is the max over all cells, not the last one.

String partition: word break

Can "sunflowerpot" be cut into words from {sun, flower, sunflower, pot, flow}? Let ok[i] say whether the first i letters can be cut cleanly. ok[0] = True: the empty start is always fine.

ok = [True] + [False] * len(s)
for i in range(1, len(s) + 1):
    for j in range(i):
        if ok[j] and s[j:i] in words:
            ok[i] = True
            break
return ok[-1]
# True: ok is True at 0, 3 (sun), 7 (sunflow), 9 (sunflower) and 12

Without the final "t" ("sunflowerpo"), measure.py prints False: no cut ends at the last letter.

7. Spot the pattern: is it 1D DP, and which variant?

Read each made-up task. Decide, name the variant and the state sentence, then reveal.

A. A frog crosses a row of stones. It can hop 1, 2 or 3 stones at a time. In how many ways can it reach the last stone?

Yes, count ways. dp[i] = ways to reach stone i; dp[i] = dp[i-1] + dp[i-2] + dp[i-3]. The stairs with one more move.

B. A vending machine takes coins of 5, 7 and 11 cents, as many as you like. What is the fewest coins for exactly 40 cents?

Yes, unbounded choices (coin change). dp[a] = fewest coins for a cents. Greedy is not safe for odd coin sets like this one.

C. Show every different way to climb 10 stairs with steps of 1 or 2, written out as lists of moves.

No, this is backtracking. It looks like the stairs, but it asks you to list every way, not count them. There are 89 lists for 10 stairs and writing them all out is the real cost. DP counts; backtracking lists.

D. A runner logs a score each day. Find the longest stretch of days (not necessarily back to back) where each score beats the one before.

Yes, ends at i (LIS). "Not necessarily back to back" means subsequence. dp[i] = longest rising run ending on day i; answer max(dp).

E. Daily temperatures are in a list. For each day, find the highest temperature in the 7 days that end on it.

No, this is a sliding window (with a monotonic deque). Each answer is about a fixed-size window, not built from a smaller answer to the same question.

F. A text message was turned into digits with a = 1 ... z = 26 and no spaces. How many messages could "2612" have been?

Yes, string partition that counts. dp[i] = ways to read the first i digits. Add dp[i-1] if the last digit is 1-9, and dp[i-2] if the last two form 10-26. This is Decode Ways.

Trigger signalsCount ways, minimum or maximum, "can you reach / make", longest subsequence, and choices that block later choices. Not DP: "list every ...", or a window over a fixed range.

8. Four classic traps

Trap 1: a greedy rule that only looks right

"Always take the biggest coin that fits" works for normal money. It fails for coins 1, 3, 4 and amount 6:

# == 7. Coin change [1, 3, 4] -> 6 ==
dp answer = 2   dp = [0, 1, 2, 1, 1, 2, 2]   coin tries = 13
greedy biggest-first = [4, 1, 1]          # 3 coins, but 3 + 3 uses 2

Fix: use DP unless you can prove the greedy rule. One small counterexample is enough to rule greedy out.

Trap 2: a wrong base case

For coin change every cell starts at infinity. Forget dp[0] = 0 ("zero coins make zero") and nothing can ever be built:

dp = [float("inf")] * (amount + 1)
# missing: dp[0] = 0
trap: forgot dp[0] = 0 -> answer -1   dp = [inf, inf, inf, inf, inf, inf, inf]

Fix: ask "what is the answer for the empty input?" It is usually 0 (cost, coins) or 1 (one way to do nothing, as in decode ways and word break).

Trap 3: the answer is not always the last cell

With an "ends at i" state, the best run may end early. For [3, 4, 1]:

lis([3, 4, 1]) = 2   dp = [1, 2, 1]   dp[-1] = 1   # return dp[-1] gives 1: wrong

Fix: say the state sentence out loud. "dp[i] = longest that ends at i" means the answer is max(dp). "dp[i] = best among the first i" means it is dp[n].

Trap 4: top-down on a long input hits the recursion limit

Python stops at about 1000 nested calls. @cache does not change the depth:

# == 11. Recursion depth trap ==
recursion limit: 1000
climb_c(5000) -> RecursionError: maximum recursion depth exceeded in comparison
two-variable climb(5000) has 1045 digits

Fix: for n in the thousands, use the bottom-up loop. (Raising the limit with sys.setrecursionlimit works sometimes but can crash Python.)

Rule to rememberProve greedy or use DP. Check dp[0]. Match the answer to the state sentence. Loops beat recursion for long inputs.
Maths

9. Complexity: count states times work per state

One formula covers almost every DP: time = number of states x work to fill one state. Memory = the cells you keep.

Stairs at n = 30: three ways to do it

Plain recursion: 1,664,079 calls, about O(1.6n). Memoised: 57 calls (2n - 3), O(n) time, O(n) memory plus an n-deep stack. Bottom-up: 30 cells, O(n) time and memory. Two variables: O(n) time, O(1) memory.

On this laptop (Apple M5, Python 3.10.20) measure.py timed the plain recursion for n = 30 at 0.11 s and the two-variable loop at 0.59 us. Your machine will differ, the gap will not.

Coin change: amount x coins

States: amounts 0 to A, so A + 1 cells. Work per cell: one try per coin. Time O(A x k) for k coins, memory O(A).

For coins 1, 3, 4 and A = 6 there were 13 tries (a coin is skipped when it is bigger than the amount).

LIS and word break: a loop inside a loop

LIS has n states and each looks back at every earlier one: n x (n - 1) / 2 comparisons. For n = 1000 that is 499,500. O(n2) time, O(n) memory. (A cleverer O(n log n) version uses binary search; it is a classic follow-up.)

Word break has n + 1 states and tries up to i cut points each, so O(n2) checks. Hidden cost: s[j:i] copies the slice, which costs up to n more. That makes it O(n3) in the worst case unless you cap j by the longest word length.

Rule to rememberCount the states, multiply by the work per state. If dp[i] reads only a fixed few earlier cells, memory can drop to O(1).

11. Your lesson's questions

Q1. How many calls does the plain recursion make for climb(7)? And with @cache?

25 plain calls, 11 with memory (2 x 7 - 3). calls(7) = 1 + calls(6) + calls(5) = 1 + 15 + 9. Set the slider in section 2 to 7 to check.

Q2. House robber on [5, 1, 1, 5]. What is the best loot, and what is the dp table?

10 (the two 5s, which are not neighbours). dp = [0, 5, 5, 6, 10]. Note that "every other house" gives only 6 here.

Q3. Min cost climbing stairs: cost = [5, 10, 3, 8], you may start on step 0 or 1 and pay a step's cost to leave it. What is dp, and the answer?

dp[i] = cheapest way to stand on step i, with dp[0] = dp[1] = 0. dp = [0, 0, 5, 8, 8], so the answer is 8 (pay 5, jump to step 2, pay 3, jump to the top).

Glossary: new words from this lesson

dynamic programming
Solve smaller copies of a problem once each, store them, build up the big answer.
subproblem
A smaller copy of the question.
overlapping subproblems
The same small question comes up many times; storing it pays off.
optimal substructure
The best big answer is built from best small answers.
state
What dp[i] means, in one sentence.
transition
The rule that builds a cell from smaller cells (the recurrence).
base case
The smallest states, known without any rule.
fill order
The order cells are filled, chosen so every read cell is ready.
memoization (top-down)
Recursion that stores each result, for example with @cache.
tabulation (bottom-up)
A loop that fills the table from the base cases upward.
rolling variables
Keep only the few cells the transition still reads: O(1) memory.
call stack
The chain of calls waiting for an answer; Python allows about 1000.
exponential
Work that multiplies by a fixed factor each time n grows by one.
subsequence
Items picked in order but not necessarily side by side.

Recap: the pattern card in one minute

Idea: the answer for n is built from answers for smaller n. Store each one so it is computed once. That turns exponential recursion (1,664,079 calls for n = 30) into a linear loop (30 cells).

Signals: count ways, min or max cost, "can you make / reach", longest subsequence, choices that block later choices.

Recipe: state sentence, transition, base cases, fill order, answer location. Write @cache recursion first, then a bottom-up loop, then rolling variables.

Variants: count ways, min / max cost, take or skip, unbounded choices, ends at i (answer max(dp)), string partition.

Cost: states x work per state. Usually O(n) or O(n x k) time; O(n2) for "look back at every earlier i".

Traps: greedy that only looks right, wrong dp[0], answer in the wrong cell, recursion depth on long inputs.

In the sandbox, run the stairs, house robber and coin change templates on your own input and compare the table with the plain recursion's call count. Try coins that cannot make the amount.
