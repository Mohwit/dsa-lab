1. Two fingers, and every move throws away a whole row of answers

You have a sorted list of numbers and a target. Find two numbers that add up to the target.

The slow way tries every pair. The two pointer way puts a finger on the smallest number and a finger on the biggest, then moves one finger per check.

Analogy: two people on one sorted bookshelf. One starts at the thin books on the left, one at the thick books on the right. Together they need a stack exactly 14 cm wide. Too thin? The left person swaps for the next thicker book. Too thick? The right person swaps for a thinner one. They meet in the middle, and nobody ever goes back.

Why is a move safe? Say the smallest number plus the biggest number is still too small. Then the smallest number is too small with every partner, because the biggest one was its best hope. So the whole row of pairs that use it can go, in one move.

Try it: the same list, two ways

The list is [1, 3, 5, 6, 8, 10, 12] and the target is 14. The grid has one cell per pair: ? is a pair not yet ruled out, a number is a sum that was checked, and x is a pair thrown away without checking.

Two pointers. Check the pair at l and r. Too small: move l right, and a whole row turns to x. Too big: move r left, and a whole column goes.

Brute force: try every pair. Take each number and add it to every number after it. The grid fills one cell per check, row by row.

3. Mental map: from a blank page to two pointers

Read this when a new problem looks familiar and you do not know how to start.

  1. SignalThe input is sorted (or you may sort it). The task is about a pair or triple with a target, a mirror check, or "do it in place with O(1) extra memory".
  2. Ask"After one comparison, can I prove that one of my two items is useless for every remaining answer?" If yes, you can move that pointer and never come back.
  3. Pick the variantEach shape has its own tell-tale sign.
    • sorted + pair to targetOpposite ends: l = 0, r = n - 1, move the side that is too small or too big.
    • reads the same both waysOpposite ends, no sort needed: compare the mirror pair, step both inwards.
    • in place, remove or keepSame direction: fast reads every item, slow marks where the next keeper goes.
    • triples, k numbersFixed i plus inner pair: sort, loop i, pair search on the right of i.
    • two sorted listsOne pointer per list: always move the one with the smaller item (merge).
    • unsorted, need original indicesNot this: a hash map finds the partner in O(n) without sorting.
    • contiguous stretchNot this: a sliding window (the two pointers bound a window).
  4. InvariantIf an answer exists, it lies between l and r. For same direction: everything left of slow is the finished output.
  5. StepsSet the pointers. Loop while l < r. Compare once. Record the answer or move exactly the pointer the comparison rules out. Return after the loop.
  6. Check< or <=? Is the input really sorted? Repeated values (3Sum)? Empty list and one item? Inner skip loops need their own l < r.

4. Four templates, one idea

Template A: opposite ends on sorted input

CodeWhat it means
def pair_sum(nums, target):Return the indices of two numbers that add up to target, or None. nums must be sorted.
l, r = 0, len(nums) - 1One finger on the smallest item, one on the biggest. The search space is every pair between them.
while l < r:Strictly less: a pair needs two different items.
s = nums[l] + nums[r]One check. This is the count shown in the players.
if s == target: return [l, r]Found it.
if s < target: l += 1Too small even with the biggest partner left: nums[l] is useless. Drop its row.
else: r -= 1Too big even with the smallest partner left: nums[r] is useless. Drop its column.
return NoneThe pointers met: the search space is empty.

Template B: opposite ends as a mirror check

No sorting here. The rule is simpler: the two ends must match, so compare them and step both in. Skip anything that is not a letter or a digit.

CodeWhat it means
while l < r:Stop when the fingers meet: a middle letter has no partner to check.
if not s[l].isalnum(): l += 1Skip a space or a mark on the left. One skip per loop turn, so the l < r test guards it.
elif not s[r].isalnum(): r -= 1The same on the right.
elif s[l].lower() != s[r].lower(): return FalseA mirror pair differs: not a palindrome.
else: l += 1; r -= 1They match: both step in.

Step through "Top spot!". It needs 3 comparisons; "race a car" fails on the 4th (both counts from measure.py).

Template C: same direction, reader and writer

Remove repeats from a sorted list in place. The reader i visits every item. The writer k marks where the next new value goes. Everything left of k is the finished answer.

CodeWhat it means
if not nums: return 0An empty list keeps nothing.
k = 1The first item is always kept, so the writer starts at slot 1.
for i in range(1, len(nums)):The reader walks every other item once.
if nums[i] != nums[k - 1]:Is this value new compared with the last kept one?
nums[k] = nums[i]; k += 1Write it into the next free slot and move the writer.
return kHow many items are kept. The tail after k is leftover junk you ignore.

On [1, 1, 2, 2, 2, 3, 4, 4] it returns k = 4 and the list ends as [1, 2, 3, 4, 2, 3, 4, 4]: only the first 4 slots matter (measure.py).

Template D: fix one, pair search the rest (3Sum)

Sort. For each i, run Template A on the part to its right with target -nums[i]. Skip a value of i you already used, and after a hit skip repeats of nums[l], so no triple is reported twice.

CodeWhat it means
nums.sort()O(n log n), cheap next to the O(n2) loop below.
for i in range(len(nums) - 2):The fixed first number of the triple.
if i > 0 and nums[i] == nums[i - 1]: continueSame first number as last time: every triple it makes was already found.
l, r = i + 1, len(nums) - 1The inner pair search starts on both ends of the rest.
s = nums[i] + nums[l] + nums[r]One check. Below zero: l += 1. Above zero: r -= 1.
out.append(...); l += 1; r -= 1A hit: record it and move both pointers.
while l < r and nums[l] == nums[l - 1]: l += 1Skip copies of the value just used, or the same triple appears again.

On [-3, -1, -1, 0, 1, 2, 4]: 4 triples after 9 checks. Trying every triple takes 35 checks for the same answer (measure.py).

Rule to rememberOpposite ends when order tells you which side to drop. Same direction when you keep some items and drop others in place. For triples, fix one and reuse the pair search.
Pattern words

5. Spot the pattern: two pointers or not?

Read each made-up task. Decide yes or no, name the variant and the clue. Then reveal.

A. A list of parcel weights is sorted from light to heavy. Find two parcels that weigh exactly 50 kg together, using O(1) extra memory.

Yes, opposite ends. Clues: sorted, a pair with a target, O(1) memory. Template A.

B. Decide if a shop sign still reads the same when the letters are reversed, ignoring spaces, commas and capitals.

Yes, opposite ends as a mirror check. No sorting needed. Template B.

C. A playlist is in random order. Return the positions of two songs whose lengths add up to exactly 30 minutes.

No: a hash map. It looks like Template A, but the list is not sorted and you need the original positions. Sorting would shuffle them and cost O(n log n). A dict of "length seen at position" answers in one O(n) pass.

D. A form has blank answers scattered through it. Squeeze out the blanks in the same list, keeping the other answers in order.

Yes, same direction. Clues: in place, keep some items, keep the order. The reader skips blanks, the writer copies keepers. Template C with a different keep test.

E. Daily rainfall is in a list. Find the longest run of back-to-back days whose total rain is at most 20 mm.

No: a sliding window. It uses a left and a right index too, but the clue is a contiguous run with a condition. The two indices bound a window, grow it on the right and shrink it on the left. That is the next lesson.

F. List every different group of three temperatures that adds up to zero.

Yes, fixed one plus inner pair. Clues: triples, a target sum, "different" (skip repeats). Template D, O(n2).

G. Two guest lists are each sorted by name. Make one sorted list of everyone.

Yes, one pointer per list. Compare the two front names, take the smaller, move that pointer. O(n + m), the merge step of merge sort.

Trigger signalsSorted input, a pair or triple with a target, a mirror check, "in place" or "O(1) extra memory", two sorted inputs. Not sorted and positions matter: think hash map. Contiguous run: think sliding window.

6. Four classic traps

Trap 1: while l <= r in a pair search

With <= the loop runs once more when both pointers sit on the same item, so one number is added to itself.

# == 4. Trap 1: `while l <= r` uses one item twice ==
pair_le([2, 5, 9], 10)  = [1, 1]   # 5 + 5, the same item twice
pair_sum([2, 5, 9], 10) = None

Fix: while l < r for pairs. (Binary search is the one that uses <=, because there a single item is a valid answer.)

Trap 2: running Template A on unsorted input

"Too small, so drop the left item" is only true when the right item is the biggest one left. Without sorting, the proof is gone and the pair can be skipped.

# == 5. Trap 2: unsorted input ==
pair_sum([1, 9, 4, 3], 7)           = None     # 4 + 3 = 7 exists
pair_sum(sorted -> [1, 3, 4, 9], 7) = [1, 2]

Fix: sort first (O(n log n)) if you may, and remember sorting changes the positions. If the original positions are the answer, use a hash map instead.

Trap 3: 3Sum without skipping repeats

Equal values make the same triple twice: once with the first 0 and 2, once with the second.

# == 6. Trap 3: 3Sum without skipping repeats ==
noskip([-2, 0, 0, 2, 2])    = [[-2, 0, 2], [-2, 0, 2]]
three_sum([-2, 0, 0, 2, 2]) = [[-2, 0, 2]]

Fix: skip i when nums[i] == nums[i - 1], and after each hit move l past copies of the value just used. Sorting is what puts copies next to each other.

Trap 4: an inner skip loop with no fence

A tempting palindrome check skips punctuation with while not s[l].isalnum(): l += 1. On a string with no letters at all, l runs off the end.

# == 7. Trap 4: inner skip loop without a bound ==
pal_buggy('?!') -> IndexError: string index out of range
is_palindrome('?!') = True

Fix: every inner loop that moves a pointer also checks l < r, or (as in Template B) skip one character per turn of the main loop.

Rule to rememberStrict l < r for pairs. Sorted, or the "drop a side" proof breaks. Skip repeats on purpose. Fence every inner loop.

7. Complexity: count the checks

Both racers below do one check per tick. The list is 0, 1, ..., n - 1 and the target is -1, so no pair works and both must finish (the worst case).

The page runs both methods with a counter. The bar scale is the pair count, so at n = 1000 the teal bar is a sliver.

# == 2. Race, no pair adds up (worst case) : nums = 0..n-1, target = -1 ==
n =   10: two pointer checks =    9   brute pair checks =     45   ratio = 5.0x
n =  100: two pointer checks =   99   brute pair checks =   4950   ratio = 50.0x
n = 1000: two pointer checks =  999   brute pair checks = 499500   ratio = 500.0x
Step 1: why two pointers makes at most n - 1 checks

The gap r - l starts at n - 1. Every check that misses moves one pointer, so the gap shrinks by exactly 1. The loop stops when the gap reaches 0.

checks <= (n - 1) n = 1000 -> at most 999

So the pair search is O(n) time and O(1) extra memory: just two integers.

Step 2: the hidden cost is the sort

If the input is not sorted yet, sorting costs O(n log n), which is more than the O(n) walk. The total is then O(n log n). sorted(nums) also makes a copy (O(n) memory); nums.sort() sorts in place, though Python's sort may still borrow up to about n / 2 slots while merging.

Step 3: 3Sum is O(n2), not O(n3)

For each of about n choices of i, the inner pair search makes at most n checks. Trying every triple is n x (n - 1) x (n - 2) / 6. On 1, 2, ..., n (no triple adds to 0):

# == 8. 3Sum cost, no triple sums to 0 (nums = 1..n) ==
n =  10: two pointer checks =     36   brute triple checks =      120   ratio = 3.3x
n = 100: two pointer checks =   4851   brute triple checks =   161700   ratio = 33.3x
n = 200: two pointer checks =  19701   brute triple checks =  1313400   ratio = 66.7x

Doubling n from 100 to 200 multiplies the two pointer count by about 4 (O(n2)) and the brute count by about 8 (O(n3)).

Rule to rememberPair search: O(n) after sorting, O(n log n) with it. Each extra fixed number adds a factor of n: 3Sum O(n2), 4Sum O(n3).

9. Your lesson's questions

Q1. Run Template A on [1, 2, 4, 7, 11] with target 15. Which indices come back, and after how many checks?

[2, 4] after 3 checks. 1 + 11 = 12 (small, l moves), 2 + 11 = 13 (small, l moves), 4 + 11 = 15. measure.py prints ([2, 4], 3).

Q2. Template C runs on [0, 0, 1, 1, 1, 2]. What is k, and what are the first k items?

k = 3, and they are [0, 1, 2]. The writer only moves when the reader finds a value different from the last kept one.

Q3. 3Sum on the 100 numbers 1, 2, ..., 100. About how many checks does trying every triple make, and how many does Template D make?

161,700 against 4,851, about 33 times fewer. Every sum is positive, so each inner search only moves r: 98 + 97 + ... + 1 checks. Both numbers come from measure.py.

Glossary: new words from this lesson

pointer
An index into a list that you move one step at a time.
two pointers
A pattern that moves two indices by a rule so each step rules out answers for good.
opposite ends
Start at index 0 and n - 1, walk towards each other. Pair sums on sorted lists, mirror checks.
same direction
A fast reader and a slow writer both walk left to right. In-place filtering and compaction.
search space
All the answers still possible. Each pointer move shrinks it.
invariant
A fact true before and after every loop step: "if an answer exists, it is between l and r".
in place
Changing the input list itself, with O(1) extra memory.
palindrome
Text that reads the same forwards and backwards.
k-sum
Find k numbers with a target sum: fix k - 2 with loops, pair search the rest.
brute force
Try everything, such as every pair. Correct, often too slow.
worst case
The input that makes a method work hardest.

Recap: the pattern card in one minute

Idea: two indices move by a rule. One comparison proves an item useless for every remaining answer, so its whole row of pairs is dropped in one step.

Signals: sorted input, a pair or triple with a target, a mirror check, "in place" or O(1) memory, two sorted inputs.

Templates: opposite ends l, r = 0, n - 1; while l < r, move the side that is too small or too big. Same direction: reader i, writer k. 3Sum: sort, fix i, pair search the rest, skip repeats.

Cost: O(n) time and O(1) memory for a pair (plus O(n log n) if you sort); 3Sum O(n2). At n = 1000: 999 checks against 499,500.

Traps: <= pairs an item with itself; unsorted input breaks the proof; repeats in 3Sum; inner skip loops without l < r.

In the sandbox, run the pair search on your own sorted list, then flip to the palindrome check and try a sentence with punctuation.
