1. Explore in rings, and the shortest route falls out for free

A graph is just things and the links between them. Cities and roads. People and friendships. Cells in a grid and the cells next to them.

The most common question is "what is the fewest number of steps from here to there?". The slow way tries every route. The pattern way spreads out in rings, one step further each time.

Analogy: a stone in a pond. Drop a stone at the start. The first ring touches everything one step away. The next ring touches everything two steps away. The first ring that reaches the goal tells you the shortest distance. No ring ever needs to come back.

Both players below answer the same question on the same seven places: fewest hops from A to G. Each link is a road you can walk both ways.

Pattern: BFS ripple. A queue holds the ring being explored. Orange rings are waiting in the queue; blue ones are done.

Slow: try every route. Walk each path that never repeats a place, and keep the shortest one that reaches G.

BFS ripple- neighbour checks
every route- neighbour checks

A neighbour check is one look along one link. Both counts come from running the code (in the page and in measure.py, which prints 16 and 42). Both find 3 hops. The slow way walked 6 complete routes to be sure.

Try it: race on a bigger map

Seven places is tiny. Now the map is an open n x n grid, from the top-left corner to the bottom-right. Pick a size and race. Guess first: how much worse does "every route" get from 4 x 4 to 5 x 5?

grid3 x 3

The page runs both searches live. measure.py prints the same numbers: 5 x 5 needs 78 BFS checks against 264,860 for every route (8,512 routes), about 3,396 times more work.

Rule to rememberVisit each place once. Mark it when you first see it, and never walk into a marked place again. That one rule turns an explosion of routes into work that grows with the size of the map.

3. Mental map: from a blank page to working code

Use this checklist when a new problem smells like a graph. It is the order to think in, not the order to type in.

  1. SignalThings that link to other things: a grid of cells, islands, friends, courses with prerequisites, words that differ by one letter, "fewest steps", "can every X reach Y", "is there a cycle", "how many groups".
  2. AskWhat is a node? What is an edge? Are edges one-way or two-way? Do edges have different costs? Write the answers down before any code.
  3. PickChoose the tool by what the question asks for:
    • fewest steps, every move costs the sameBFS with a queue. The first time you reach the goal is the shortest.
    • count or measure regions, fill an areaDFS (or BFS) from every unvisited cell. Each start is one component.
    • prerequisites, an order, a cycle in one-way linksTopological sort with Kahn's in-degree queue.
    • links arrive one at a time, "connected yet?"Union-find with path compression and union by size.
    • links have different costsNot this pattern: Dijkstra (shortest paths lesson).
    • grid where you only move right or down and count waysNot a search: that is dynamic programming.
  4. InvariantA node enters the visited set exactly once, at the moment it is first discovered. So each node is handled once and each edge is looked at once per direction: O(V + E).
  5. Steps1. Build the adjacency list (or write the four grid moves). 2. Put the start in the visited set and the queue or stack. 3. Loop: take one node, look at each neighbour, skip visited ones, mark and push the rest. 4. Read the answer from what you recorded: distances, counts, an order, or the number of groups.
  6. CheckMark visited on push, not on pop. Add undirected edges both ways. Disconnected graphs need an outer loop over every node. Deep grids can blow Python's recursion limit: use an explicit stack. Topological sort: if the order is shorter than the number of nodes, there is a cycle.

4. Four templates cover this pattern

Ripple vs cave: the same graph, two visit orders

BFS takes the oldest discovery first (a queue). DFS takes the newest (the call stack). Step both and watch the visit order.

BFS: ring by ring. A, then all of A's neighbours, then theirs.

DFS: one tunnel at a time. A, then dive into B as deep as it goes, then back up.

measure.py prints BFS order A B C D E F G and DFS order A B E C F D G. Both look along 18 links: each of the 9 edges once from each end.

Template A: BFS for fewest steps

CodeWhat it means
from collections import dequeA queue with O(1) adds at the back and takes from the front.
def fewest_hops(adj, start, goal):adj maps each node to its neighbours.
dist = {start: 0}Distance so far. Being in dist also means "visited".
q = deque([start])The frontier: discovered, not yet explored.
while q:Keep going until no discovered node is left.
node = q.popleft()Oldest first. This is what makes it a ripple.
if node == goal: return dist[node]The first time the goal comes out, its distance is the smallest.
for nb in adj[node]:One neighbour check per link.
if nb not in dist:Skip anything already discovered.
dist[nb] = dist[node] + 1Mark it now, on push, with one more step.
q.append(nb)Join the back of the line.
return -1The ripple died out: the goal cannot be reached.

For a grid, swap adj[node] for the four moves (1, 0), (-1, 0), (0, 1), (0, -1) plus a bounds check. For "many sources at once" (every rotten orange starts rotting together), put all of them in the queue at distance 0.

Template B: DFS flood fill (count islands)

A 1 is land, a 0 is water. Every time the scan meets fresh land, that is a new island; the DFS then sinks the whole island so it is never counted again.

Template C: topological sort (Kahn's algorithm)

Getting dressed has rules: underwear before pants, pants and socks before shoes, shirt before tie. The in-degree of an item is how many items must come first. Anything at zero is free to put on now.

CodeWhat it means
for a, b in edges: adj[a].append(b); indeg[b] += 1One-way edges: a must come before b. Count b's waits.
q = deque(v for v in nodes if indeg[v] == 0)Everything with no prerequisites can start now.
v = q.popleft(); order.append(v)Do one free task.
for w in adj[v]: indeg[w] -= 1Each task after v has one less thing to wait for.
if indeg[w] == 0: q.append(w)Its last prerequisite is done: it is free now.
return order if len(order) == len(nodes) else NoneNodes on a cycle never reach zero. A short order means a cycle.

measure.py prints: under, socks, shirt, pants, tie, shoes, belt, coat. Other orders are valid too; this is the one a first-in first-out queue gives.

Template D: union-find for merging groups

Think of friend groups. Each group has a leader. find(x) walks up "who do you follow?" until it reaches someone who follows themselves. union(a, b) makes one leader follow the other.

CodeWhat it means
self.parent = list(range(n))Everyone starts as their own leader: n groups.
self.size = [1] * nGroup sizes, kept on the leaders.
while self.parent[x] != x:Not a leader yet: keep walking up. Each loop is one hop.
self.parent[x] = self.parent[self.parent[x]]Path compression (halving form): skip to your grandparent, so the next walk is shorter.
ra, rb = self.find(a), self.find(b)Find both leaders.
if ra == rb: return FalseAlready one group. In "redundant connection" this edge is the extra one.
if self.size[ra] < self.size[rb]: ra, rb = rb, raUnion by size: the smaller group joins the bigger one.
self.parent[rb] = ra; self.size[ra] += self.size[rb]Merge: one leader now follows the other.

Pattern words

5. Spot the pattern: which graph tool, if any?

Read each made-up task. Name the nodes, the edges, and the tool. Then reveal.

A. A knight sits on a chessboard. What is the fewest number of moves to reach a given square?

BFS. Nodes are squares, edges are the 8 knight jumps, every jump costs 1. "Fewest moves" with equal costs is the BFS signal.

B. A school lists which classes need which other classes first. Can a student take all of them?

Topological sort. One-way edges from a prerequisite to the class. Run Kahn; if the order has fewer classes than the list, there is a cycle and the answer is no.

C. A map gives each road a driving time. Find the quickest drive from home to the airport.

Not plain BFS. Roads have different costs, so the first time BFS reaches the airport may not be the quickest. Use Dijkstra with a heap (the shortest paths lesson).

D. A photo is a grid of colours. Tapping a pixel repaints it and every same-coloured pixel touching it.

DFS or BFS flood fill. Nodes are pixels, edges join same-coloured neighbours. One fill from the tapped pixel. Careful: if the new colour equals the old one, return at once or you loop forever.

E. Network cables are plugged in one by one. After each cable, report how many separate networks there are.

Union-find. Links arrive over time and you need the group count after each. Start at n groups; each union that returns True removes one. Re-running DFS after every cable would be far slower.

F. A robot moves only right or down on a grid. How many different routes reach the far corner?

Not a graph search. It looks like a grid problem, but it asks to count routes, not to reach or measure. Each cell's count is the sum of the cell above and the cell to the left: dynamic programming.

G. Words in a list are linked if they differ by one letter. How few changes turn "cold" into "warm"?

BFS on a hidden graph. Nodes are words; edges are one-letter changes. You build neighbours on the fly (try each position and each letter). This is Word Ladder.

Trigger signalsGrids of cells, islands and regions, "fewest steps" with equal costs, prerequisites and orders, cycles in one-way links, "how many groups" and "are these connected", and any list of pairs that link things.

6. Four classic traps

Trap 1: marking visited when you pop, not when you push

If you only mark a node when it leaves the queue, two neighbours can both push the same node before it comes out. The answer is still right, but the queue fills with copies.

# wrong: mark on pop
node = q.popleft()
if node in seen: continue
seen.add(node)
for nb in adj[node]:
    if nb not in seen: q.append(nb)

# == 6a. measure.py: pushes onto the queue, whole graph ==
7-node graph: mark on pop = 10 pushes   mark on push = 7 pushes
10x10 grid:   mark on pop = 181 pushes  mark on push = 100 pushes
50x50 grid:   mark on pop = 4901 pushes mark on push = 2500 pushes

Fix: add to seen right before q.append(nb), and put the start in seen at the beginning. Worse versions without the continue explore copies again and can time out.

Trap 2: recursion depth on big grids

Recursive DFS on a grid that is all land goes one call deeper per cell. Python stops at 1000 calls by default.

# == 6b. measure.py ==
recursion limit = 1000
20x20 all land, recursive DFS -> 1 island
40x40 all land, recursive DFS -> RecursionError: maximum recursion depth exceeded in comparison
40x40 all land, stack DFS -> 1 island

Fix: use an explicit stack (stack = [(r, c)], while stack: stack.pop(), mark on push) or BFS. Raising the limit with sys.setrecursionlimit helps a little, but very deep recursion can still crash the program.

Trap 3: an undirected edge added only one way

Friendship goes both ways. If you only store adj[a].append(b), a search from b never finds a.

n = 3, edges = [(1, 0), (2, 1)]
one-way adjacency -> 3 components   # wrong: 0 cannot see 1
both ways         -> 1 component

Fix: for undirected input, add adj[a].append(b) and adj[b].append(a). For directed input (prerequisites), add one way only, in the right direction.

Trap 4: finding a "cycle" with a plain visited set in a directed graph

In a diamond A to B, A to C, B to D, C to D, DFS reaches D twice. A plain visited set calls that a cycle. It is not: you cannot get back to A.

diamond: plain visited says cycle = True   three colours say cycle = False
kahn on diamond: ['A', 'B', 'C', 'D']

Fix: use Kahn (a short order means a cycle) or three states in DFS: new, on the current path, finished. Only meeting a node that is on the current path is a cycle.

Rule to rememberMark on push. Use a stack, not recursion, when the map can be thousands of cells deep. Two-way edges go in twice. In one-way graphs, a cycle means "back to a node still on my path".
Maths

7. Complexity: count the work

Step 1: BFS and DFS are O(V + E)

Each node is put in the visited set once, so it is popped once: V pops. Each node looks at its own neighbour list once. Added over all nodes, that is every edge once from each end: 2E checks.

The 7-node graph has 9 edges, and both searches did exactly 18 neighbour checks. A 100 x 100 grid has 10,000 cells; measure.py counts 39,600 checks for a full BFS, which is exactly 2 x (number of edges).

time O(V + E), extra space O(V) for the visited set and the queue or stack
Step 2: why trying every route explodes

The number of routes that never repeat a cell grows faster than any power of n. On open grids measure.py finds 2, 12, 184 and 8,512 routes for 2 x 2 up to 5 x 5. BFS only grows with the number of cells: 6, 22, 46, 78 checks.

Step 3: topological sort and union-find

Kahn builds in-degrees (E steps), pops each node once (V) and lowers each in-degree once (E): O(V + E).

Union-find with union by size and path compression costs about O(α(n)) per call on average, where α is the inverse Ackermann function. It is at most 4 for any input you could store. Treat it as O(1). Without either trick, a chain makes each find O(n): 499,500 hops for 1000 people in section 4.

Step 4: hidden costs

list.pop(0) shifts every item: O(n) per pop, which makes "BFS" O(V2). Use deque.popleft(). Building the adjacency list costs O(V + E) memory. Recursive DFS also uses O(depth) call stack, up to V frames.

Check yourself

9. Your lesson's questions

Q1. A path graph A - B - C - D - E. Start at C, neighbours listed in alphabetical order. Write the BFS order and the DFS order.

BFS: C B D A E. DFS: C B A D E. BFS takes both one-step neighbours before any two-step one. DFS runs to the end of the B side before coming back for D. measure.py prints both.

Q2. Kahn's algorithm on nodes a, b, c with edges a to b, a to c, c to b. What order comes out?

a, c, b. Only a starts at in-degree 0. Popping a lowers b to 1 and c to 0, so c joins the queue. Popping c lowers b to 0. measure.py prints ['a', 'c', 'b'].

Q3. Union-find on 5 people: union(0, 1), union(1, 2), union(3, 4), union(2, 0). Which call returns False, and how many groups remain?

union(2, 0) returns False, because 0 and 2 already share a leader. 2 groups remain: {0, 1, 2} and {3, 4}. That False is exactly how Redundant Connection finds the extra edge.

Glossary: new words from this lesson

graph, node, edge
Things (nodes) and the links between them (edges). V nodes, E edges.
neighbour
A node one edge away.
adjacency list
A dict from each node to the list of its neighbours.
directed / undirected
One-way links / two-way links. Undirected edges are stored both ways.
visited set
Nodes already discovered. Mark on push so nothing is queued twice.
frontier
Discovered but not yet explored: the queue in BFS.
BFS
Breadth-first search: ring by ring with a queue. Fewest steps when every step costs the same.
DFS
Depth-first search: one path to its end, then back up. Recursion or a stack.
queue / stack / deque
First in first out / last in first out / Python's double-ended queue with O(1) popleft.
connected component
A group of nodes that reach each other and nothing else.
flood fill
Painting every cell joined to a start cell; used to count and measure regions.
cycle
A path that returns to its start.
in-degree
Number of edges pointing into a node: prerequisites still waiting.
topological order, Kahn's algorithm
An order where every edge points forward; built by repeatedly taking a node with in-degree 0.
union-find (DSU), find, union, root
Groups with a leader each; find gives the leader, union merges two groups.
path compression, union by size
The two tricks that keep union-find trees flat, so each call is nearly O(1).

Recap: the pattern card in one minute

Idea: name the nodes and edges, then pick a tool. BFS spreads in rings (fewest equal-cost steps). DFS dives (regions, reachability). Kahn peels off tasks with in-degree 0 (orders, cycles). Union-find merges groups (connectivity as links arrive).

Signals: grids, islands, "fewest steps", prerequisites, "is there a cycle", "how many groups", lists of pairs.

Template: seen = {start}, q = deque([start]); pop, look at each neighbour, skip seen, mark and push. Kahn: in-degree counts, queue of zeros, a short order means a cycle. DSU: parent, size, find with halving, union small into big.

Cost: O(V + E) time and O(V) space for BFS, DFS and Kahn; about O(1) per union-find call. Trying every route instead: 264,860 checks against 78 on a 5 x 5 grid.

Traps: mark on push, not pop; recursion depth on big grids; undirected edges both ways; directed cycles need "on my current path", not just "visited".

In the sandbox, type your own edges and run BFS, DFS or a topological sort. Try a ring, two separate groups, and a one-way cycle.
