1. One in, one out: never recount the whole stretch

Many questions ask about a contiguous stretch: "the best 4 days in a row", "the longest piece of text with no repeated letter".

The slow way rebuilds every stretch from nothing. The window way keeps a running summary and fixes it up as the stretch slides along.

Analogy: the view from a train window. As the train rolls forward, one tree enters the window on the right and one tree leaves on the left. You do not recount the whole forest to know what you can see. You add the newcomer and forget the one that left.

Try it: best total of 4 numbers in a row

The list is [3, 1, 4, 1, 5, 9, 2, 6, 5, 3] and the window holds k = 4 numbers. The blue cells are the window. A touch is one number added to or taken from a total.

Slide the window. Add up the first 4 once. Then each slide adds the number that enters and takes away the one that leaves: 2 touches.

Brute force: recount each window. Every window adds its 4 numbers from scratch, even though 3 of them were just added.

3. Mental map: from a blank page to a window

Read this when a new problem mentions a stretch and you do not know how to start.

  1. Signal"Subarray" or "substring" (contiguous), plus longest, shortest, best, or count with a condition. "At most k", "k in a row", "contains all of".
  2. Ask"If I add one item on the right or remove one on the left, can I update my summary in O(1)? And if a window breaks the rule, does every bigger window that holds it break it too?"
  3. Pick the variantThe wording tells you which.
    • "k in a row", size givenFixed window: add a[r], remove a[r - k], update the answer.
    • longest with a ruleVariable window: grow, shrink while invalid, update the answer after the shrink.
    • shortest that reaches a goalVariable window: grow, and while valid record the answer, then shrink.
    • "at most k" of somethingCount map; shrink while len(count) > k. To count windows with exactly k: count(at most k) minus count(at most k - 1).
    • max or min of each windowFixed window plus a monotonic deque.
    • sum equals k, negatives allowedNot this: prefix sums with a hash map. Shrinking is not safe with negatives.
    • pick any items, not in a rowNot this: subsets need hashing, sorting or DP.
  4. InvariantAfter the shrink loop, the window [l, r] is valid and is the longest valid window that ends at r.
  5. StepsFor each r: add a[r] to the summary. While invalid: remove a[l], l += 1. Update the answer with r - l + 1.
  6. CheckAnswer updated at the right moment? Zero counts deleted from the map? Negative numbers (the shrink rule breaks)? Off by one: the length is r - l + 1. Empty input?

4. Templates: one fixed, three variable

Template A: fixed-size window

CodeWhat it means
def max_sum_k(nums, k):The best total of k numbers in a row. Assumes 1 <= k <= len(nums).
total = sum(nums[:k])Build the first window once: k touches.
best = totalThe first window is the best so far.
for r in range(k, len(nums)):r is the item entering the window.
total += nums[r] - nums[r - k]One in, one out: 2 touches. nums[r - k] is the item that just left.
best = max(best, total)Every window of size k is valid, so update every time.
return bestO(n) time, O(1) memory.

The left player in section 1 runs exactly this.

Template B: longest valid window (grow, shrink while invalid, then update)

CodeWhat it means
count = {}The summary: how many of each letter are in the window.
l = best = 0The window starts empty at index 0.
for r, ch in enumerate(s):Expand: every letter enters once.
count[ch] = count.get(ch, 0) + 1Add the newcomer to the summary.
while count[ch] > 1:Invalid: ch is now in there twice. Only ch can be repeated, because the window was valid before it came in.
count[s[l]] -= 1; l += 1Shrink: the leftmost letter leaves.
best = max(best, r - l + 1)After the loop: the window is valid again, so it may count.

On "abcbdab" the longest stretch with no repeat has length 4 ("cbda"). The window makes 11 moves; restarting from every letter reads 22 letters (measure.py).

Template C: "at most k different" with a count map

The same shape. Only the rule changes, and one line matters a lot: delete a letter from the map when its count reaches 0, so len(count) is the number of different letters really in the window.

CodeWhat it means
while len(count) > k:Too many different letters: invalid.
left = s[l]; count[left] -= 1The leftmost letter leaves.
if count[left] == 0: del count[left]Gone from the window, so gone from the map (trap 2).
l += 1Shrink by one.
best = max(best, r - l + 1)After the loop, as in Template B.

On "abaccbab" with k = 2 the answer is 3 after 13 window moves (measure.py). This is the template the sandbox runs.

Template D: shortest window that reaches a goal (update inside the loop)

Flip the question: the shortest stretch whose total is at least a target. Now a window is "good" when it reaches the target, and you want it as small as possible, so you record it while it is good, then shrink to try for smaller.

CodeWhat it means
total += xExpand.
while total >= target:The window reaches the goal.
best = min(best, r - l + 1)Inside the loop: record before shrinking, because after the shrink it may no longer reach the goal.
total -= nums[l]; l += 1Shrink to look for something shorter.
return 0 if best == float('inf') else bestNo window ever reached the goal: answer 0.

On [2, 1, 5, 1, 3, 2] with target 8 the answer is 3 (5 + 1 + 3 = 9), after 9 window moves. Only works when every number is 0 or more (trap 3).

Rule to rememberLongest: shrink while invalid, then record. Shortest: while good, record, then shrink. The update line moves; the rest of the template stays the same.
Pattern words

5. Spot the pattern: window or not?

Read each made-up task. Decide yes or no, name the variant and the clue. Then reveal.

A. A radio station logs which band played each song. Find the longest run of songs where no band plays twice.

Yes, variable window, longest. Clues: a run (contiguous), longest, "no repeat" rule. Template B.

B. A shop has daily sales for a year. Find the best total over any 7 days in a row.

Yes, fixed window. Clue: "7 days in a row", the size is given. Template A with k = 7.

C. Daily rainfall (never negative) is logged. Find the fewest back-to-back days that together bring at least 50 mm.

Yes, variable window, shortest. Clues: back-to-back, fewest, "at least". Never negative, so shrinking is safe. Template D: record inside the loop.

D. A bank account has deposits and withdrawals. Count how many stretches of back-to-back transactions add up to exactly zero.

No: prefix sums with a hash map. It says "back-to-back", but withdrawals are negative. Adding an item can lower the total, so "too big, shrink" proves nothing. Count running totals seen before instead.

E. Prices are sorted. Find two prices that add up to exactly 100.

No: two pointers from opposite ends. Two items anywhere in the list, not a stretch. Nothing between them matters.

F. Does a long text contain any shuffle of the letters of a short code word as one block?

Yes, fixed window with a count map. The block has the code word's length. Slide it and compare letter counts (one in, one out).

G. For every 3 hours in a row, report the highest temperature in those 3 hours.

Yes, fixed window plus a monotonic deque. A total can be fixed up by one in and one out, but a maximum cannot: when the max leaves, what is next? The deque keeps the candidates in order.

Trigger signalsContiguous plus longest / shortest / best / count, "k in a row", "at most k". Negatives with "sum equals": prefix sums. Two items anywhere: two pointers or a hash map.

6. Three classic traps

Trap 1: updating the answer before the window is valid again

In a "longest" window, if best = max(...) sits above the shrink loop, it measures a window that still breaks the rule.

# == 4. Trap 1: update the answer before the window is valid again ==
early('abcc') = 4   # 'abcc' has a repeat
fixed('abcc') = 3

Fix: for longest, update after the while. For shortest, update inside it, before you shrink (Template D). Ask: "at this line, is the window one I am allowed to count?"

Trap 2: a zero count left in the map

Lowering a count to 0 does not remove the key. len(count) still counts that letter, the window never looks valid, and l runs off the end.

# == 5. Trap 2: a zero count left in the map ==
nodelete('abaccbab', 2) -> IndexError: string index out of range
longest_k_distinct('abaccbab', 2) = 3

Fix: if count[left] == 0: del count[left]. Or keep a separate "different letters" counter that goes up when a count goes 0 to 1 and down when it goes 1 to 0.

Trap 3: negative numbers

Template D assumes growing the window never lowers the total. With a negative number, a window can fail now and succeed after you add more, so the template gives up too early.

# == 6. Trap 3: negative numbers break the shrink rule ==
shortest_at_least([1, -5, 6], 6) = 0   # but [6] alone works
shortest_brute([1, -5, 6], 6)    = 1

Fix: check the constraints. With negatives, use prefix sums (with a hash map, or a monotonic deque for "at least").

Rule to rememberRecord only windows you are allowed to count. Delete keys whose count hits 0. Shrinking is only safe when "bigger window" means "more of the thing", which needs non-negative numbers.

7. Complexity: race the slide against the recount

Pick a list size and a window size, then race. Each racer does one touch per tick. Watch what happens when k grows.

The page runs both methods with a counter. Slide: k + 2 x (n - k). Recount: (n - k + 1) x k. The recount is worst when k is about n / 2.

Step 1: why a variable window is O(n), even with a loop inside a loop

The inner while looks like it could make this O(n2). It cannot. r moves right n times. l only moves right, and never past r, so it moves at most n times in total, across all turns of the outer loop.

window moves <= n (adds) + n (removes) = 2n

Counted on random strings over 10 letters (seed 7):

# == 7. Cost of the variable window ==
n =   100: window moves =   198 (at most 2n =   200)   brute reads =    479
n =  1000: window moves =  1995 (at most 2n =  2000)   brute reads =   4584
n = 10000: window moves = 19997 (at most 2n = 20000)   brute reads =  46474
Step 2: when the brute force really hurts

On random text over 10 letters the restart-from-every-letter brute force breaks within about 10 reads, so it is only a few times slower. Its true cost shows when windows rarely break. A string of only a and b with "at most 2 different" never breaks, so the brute reads n x (n + 1) / 2 letters:

two letters, k = 2, n =  100: window moves =  100   brute reads =   5050
two letters, k = 2, n = 1000: window moves = 1000   brute reads = 500500

Big-O is about this worst case: brute O(n2), window O(n).

Step 3: memory and hidden costs

A total is O(1) memory. A count map holds at most one key per different item in the window: O(alphabet), which is O(1) for 26 letters and up to O(n) for numbers. Slicing such as sum(nums[l:r + 1]) inside the loop secretly rescans the window and brings back O(n x k).

Rule to rememberEach index enters once and leaves once: O(n) time. Memory is the summary: O(1) for a total, O(different items) for a count map.

Check yourself

9. Your lesson's questions

Q1. Template A on [2, 8, 1, 7, 3] with k = 2. What is the best total? How many touches does sliding take, and how many does recounting take?

Best 10, and 8 touches each. With k = 2 a slide costs 2 touches and a recount also costs 2, so there is no saving. The slide pays off as k grows. measure.py prints (10, 8) for both.

Q2. Template B on "pqrqs". What is the answer, and how many window moves (adds plus removes) happen?

3, after 7 moves. 5 letters enter. When the second q enters, p and the first q leave (2 removes). The longest valid windows are "pqr" and "rqs".

Q3. Template D on [1, 2, 3, 4, 5] with target 9. What comes back? What would go wrong if the best = min(...) line moved below the while loop?

2 (4 + 5), after 9 window moves (measure.py). Below the loop, the window has already been shrunk until it no longer reaches 9, so you would record windows that fail the goal.

Glossary: new words from this lesson

contiguous
Next to each other with no gaps: a subarray or substring.
window
The stretch from l to r; its length is r - l + 1.
fixed-size window
Always k items: one in, one out per step.
variable-size window
Grows on the right, shrinks on the left while a rule is broken.
window summary
A total or a count map kept up to date instead of rescanning.
validity rule
The test a window must pass, such as "at most k different letters".
expand / shrink
Move r right and add its item / move l right and remove its item.
touch
This lesson's unit of work: one number added to or taken from a total.
monotonic deque
A double-ended queue kept in sorted order, so its front is the window's max or min.
prefix sums
Running totals; the tool for "sum equals k" when numbers can be negative.

Recap: the pattern card in one minute

Idea: keep a summary of a contiguous window and update it by one item in and one item out, instead of rebuilding each stretch.

Signals: subarray or substring, longest / shortest / best / count, "k in a row", "at most k", "contains all of".

Templates: fixed: total += a[r] - a[r - k]. Variable: for each r, add a[r]; while invalid: remove a[l], l += 1; then best = max(best, r - l + 1). Shortest: record inside the while, before shrinking.

Cost: O(n) time, because l and r each move at most n times; memory O(1) for a total, O(different items) for a count map. At n = 1000, k = 500: 1,500 touches against 250,500.

Traps: recording before the window is valid; zero counts left in the map; negative numbers (use prefix sums).

In the sandbox, run "at most k different" on your own string, then switch to the fixed window and try a big k.
