1. Sort by start, then only look back one step

An interval is a pair [start, end]: a meeting from 2 to 5, a booking from day 7 to day 9.

Questions about many intervals ("which ones clash?", "join the ones that touch") look like they need every pair compared. They do not. Once the intervals are in order of start time, each one can only clash with the most recent one you kept.

Analogy: booking meeting rooms from a calendar. Nobody checks every meeting against every other meeting. You read the day from morning to evening. For each new meeting you ask one question: "has the last meeting I wrote down ended yet?"

Here is the job. Join every group of overlapping intervals in [[7, 9], [1, 3], [2, 5], [10, 11], [6, 8]]. In the pictures, each row is one interval drawn as a bar on a time line. Column t is the slot from t to t + 1, so the bar for [1, 3] fills slots 1 and 2 and stops at time 3.

Try it: the same intervals, two ways

Press Step or Play on each player.

Slow: compare every pair. No sorting. Test each pair for overlap and put overlapping ones in one group.

Pattern: sort, then scan. Sort by start. Compare each interval only with the last merged one.

Both find [[1, 5], [6, 9], [10, 11]]. measure.py prints 10 pair checks and 4 scan checks for these five intervals.

Rule to rememberSort first. After sorting by start, an interval can only overlap the group just before it, so one look back is enough.

4. Mental map: from a blank page to working code

Read this when a problem hands you pairs of numbers.

  1. SignalThe input is pairs [start, end]: meetings, bookings, ranges, balloons, time slots. The words "overlap", "merge", "clash", "free time", "rooms", "remove the fewest".
  2. Ask"If I sort the intervals, what is the one thing I must remember about the ones already seen?" Usually it is the last end time, or a count of what is running.
  3. PickWhich question is it?
    • join the ones that overlapMerge: sort by start, compare with the last merged end.
    • one new interval into a sorted listInsert: copy the ones before it, absorb the ones that overlap, copy the rest. No sort needed.
    • how many at once? how many rooms?Count overlaps: sweep line of +1 / -1 events, or a heap of end times.
    • remove the fewest so none clashGreedy by end: sort by end, keep the one that ends first.
    • two sorted lists, common timeIntersection: two pointers, move the one that ends first.
    • can one person attend all?Sort by start, check each neighbour pair once.
  4. InvariantAfter sorting by start, the merged list so far has no overlaps, and only its last interval can still grow.
  5. Steps1. Sort by the right key. 2. Keep a small memory (the last end, or a running count). 3. For each interval, one comparison decides: join, keep, or remove. 4. Do not forget the last group.
  6. CheckDo touching intervals count as overlapping here? Did you sort, and by the right key? Do you take the max of the ends? Does an empty list work?
Not intervalsMany "range" questions about one array (the sum from index l to r) are prefix sums. A run of back-to-back items is a sliding window. Intervals means many separate start and end pairs.

5. Templates for the four common questions

Template A: merge (sort by start)

CodeWhat it means
def merge(intervals):Join every group of overlapping intervals.
out = []Merged intervals so far. Only the last one can still grow.
for s, e in sorted(intervals):Sort by start (Python sorts pairs by the first item, then the second). O(n log n).
if out and s <= out[-1][1]:One look back: does it start before the last one ends? <= joins touching ones.
out[-1][1] = max(out[-1][1], e)Stretch the last one. max, because the new one may sit inside it.
else: out.append([s, e])A gap: start a new merged interval.
return outAlready sorted and free of overlaps.

Template B: insert into a sorted list (no sort)

CodeWhat it means
s, e = newThe interval to add. The list is already sorted and has no overlaps.
while i < n and intervals[i][1] < s:Phase 1: these end before the new one starts. Copy them.
while i < n and intervals[i][0] <= e:Phase 2: these overlap the new one. Grow it: s = min(...), e = max(...).
out.append([s, e])Add the grown interval once.
out.extend(intervals[i:])Phase 3: the rest start after it. Copy them. O(n) in total.
 
# == 3. Templates ==
insert([[1, 2], [4, 6], [8, 10]], [5, 9]) = [[1, 2], [4, 10]]
insert([[1, 2], [4, 6]], [7, 8])          = [[1, 2], [4, 6], [7, 8]]

Template C: how many rooms? (sweep line, or a heap)

CodeWhat it means
events.append((s, 1)); events.append((e, -1))A start needs a room (+1); an end frees one (-1).
events.sort()By time. At the same time, -1 comes before +1, so a room freed at 4 can be used again at 4.
rooms += dRooms busy right after this event.
best = max(best, rooms)The busiest moment is the answer.
for s, e in sorted(meetings): (heap way)The other classic: meetings by start, and a heap ends of rooms in use.
if ends and ends[0] <= s: heapq.heappop(ends)The earliest-finishing room is free: reuse it.
heapq.heappush(ends, e); return len(ends)This meeting takes a room. The heap size at the end is the room count.

Template D: remove the fewest (greedy by end)

CodeWhat it means
for s, e in sorted(intervals, key=lambda iv: iv[1]):Sort by end. The one that ends first leaves the most room for the others.
if end is not None and s < end:It starts before the last kept one ends: a clash. < lets touching ones stay.
removed += 1Drop it. It ends no earlier than the kept one, so dropping it is never worse.
else: end = eNo clash: keep it, and remember its end.

Pattern words

6. Spot the pattern: is this an intervals problem?

Read each made-up task. Decide yes or no, name the variant, and name the clue. Then reveal.

A. A hotel has every guest's check-in and check-out day. Report the stretches of days when the hotel had anyone staying.

Yes: merge. Clue: start and end pairs, and "stretches" means joining the ones that overlap. Sort by check-in, stretch the last stretch.

B. A gym lists every class with its start and end time. What is the fewest number of studios it needs?

Yes: count overlaps (meeting rooms). Clue: "how many at once". Sweep line of +1 and -1 events, or a heap of end times.

C. A weather station logs rainfall per day. Many times a day, someone asks for the total rain between day l and day r.

No, not this pattern. It talks about ranges, but there is one array and many sum questions. Nothing overlaps or merges. That is prefix sums: one subtraction per question.

D. Balloons float above a line, each covering a stretch from x1 to x2. One upward dart pops every balloon over its x. What is the fewest number of darts?

Yes: greedy by end. Sort by end; throw a dart at the first end and it pops every balloon that starts by then. It is the twin of "remove the fewest".

E. Given an unsorted list of whole numbers, find the longest run of values that follow each other, like 4, 5, 6, 7.

No, not this pattern. The answer is a range, but the input is single numbers, not start and end pairs. Put them in a set and grow each run from its smallest value (arrays and hashing).

F. Two friends each have a sorted list of free time slots. List the times when both are free.

Yes: intersection. Both lists are already sorted, so no sort. Two pointers: the overlap is [max(starts), min(ends)] when it is not empty; then move past whichever slot ends first.

Trigger signalsStart and end pairs; "overlap", "merge", "rooms", "free time", "fewest to remove". One array with range questions is prefix sums, not intervals.

7. Four classic traps

Trap 1: touching endpoints

Does a meeting ending at 3 clash with one starting at 3? For rooms, no: the first has left. If the sweep puts the +1 before the -1 at the same time, it counts one room too many.

# == 5. Traps ==
touching [[1, 3], [3, 5]]: rooms fixed = 1  rooms bug (start first) = 2
merge touching [[1, 3], [3, 5]] = [[1, 5]]   # merge problems count touching as overlap

Fix: read the problem's rule, then pick < or <= on purpose. For rooms, let ends sort before starts (the tuple (t, -1) does). For merge, LeetCode 56 joins touching intervals, so <=.

Trap 2: sorting by the wrong key

For "remove the fewest", sorting by start keeps a long interval just because it starts first, and then everything inside it gets removed.

erase [[1, 10], [2, 3], [4, 5]]: by end = 1  by start (bug) = 2  brute = 1

Fix: greedy keeping needs sort by end. Merging needs sort by start. Say which and why before you code.

Trap 3: replacing the end instead of taking the max

When the new interval sits inside the last one, setting the end to the new end shrinks it.

merge [[1, 10], [2, 3]]: fixed = [[1, 10]]  replace-end bug = [[1, 3]]

Fix: out[-1][1] = max(out[-1][1], e).

Trap 4: forgetting to sort

The one-look-back rule is only true for sorted input. Unsorted, an early interval can swallow ones it never touched.

merge [[4, 6], [1, 2], [2, 5]]: fixed = [[1, 6]]  no-sort bug = [[4, 6]]

Fix: sorted(intervals) first, unless the problem promises sorted input (insert, intersection).

Rule to rememberDecide what touching means. Sort, and by the right key. Stretch with max.
Maths

8. What it costs

Step 1: the sort is the whole bill

The scan after sorting does n - 1 checks: O(n). The sort is O(n log n). So merge, rooms and remove-fewest all cost O(n log n) time.

For n = 1000, Python's sort made 8,630 comparisons and the scan 999 checks. Comparing every pair would be 499,500.

Step 2: where n x (n - 1) / 2 comes from
(n - 1) + (n - 2) + ... + 1 = n x (n - 1) / 2

For the five intervals in section 1: 5 x 4 / 2 = 10 pair checks against 4 scan checks.

Step 3: memory, the heap, and insert

sorted makes a copy: O(n) extra space, and the output can be O(n). The sweep line holds 2n events. The heap holds at most one end time per room, so O(n), and each push or pop costs O(log n).

Insert needs no sort because the list is given sorted: one pass, O(n).

Step 4: why greedy beats trying every choice

Trying every set of intervals to keep is 2n sets: 32 for the five intervals in template D, against 4 greedy checks. At n = 30 that is over a billion sets.

Why greedy by end is safe: whatever the best answer keeps first, swap it for the interval that ends first. It ends no later, so it clashes with nothing the best answer kept after it. Repeat, and the greedy answer is just as big.

10. Your lesson's questions

Q1. What does Template A return for [[1, 4], [4, 5]]?

[[1, 5]]. 4 <= 4, so the touching pair merges. measure.py prints [[1, 5]].

Q2. How many rooms do the meetings [[0, 30], [5, 10], [15, 20]] need?

2. The long meeting holds one room all day. The two short ones never clash with each other, so they share the second room.

Q3. Template D on [[1, 2], [2, 3], [3, 4], [1, 3]]: how many are removed?

1. Sorted by end: [1, 2], then [2, 3] and [1, 3] (both end at 3), then [3, 4]. [1, 3] starts at 1, before the kept end 3, so it goes. The touching ones stay.

Q4. With 2000 intervals, how many pair checks does the slow way make, and how many scan checks does the fast way make after sorting?

1,999,000 pair checks (2000 x 1999 / 2) against 1,999 scan checks. Both are printed by measure.py.

Glossary: new words from this lesson

interval
A [start, end] pair for a stretch of time or numbers.
overlap
Two intervals share some time: a[0] <= b[1] and b[0] <= a[1] for closed ends.
merge
Replace a group of overlapping intervals with one from the smallest start to the largest end.
touching
One ends where the next starts. Whether it counts as overlap depends on the problem.
half-open
[s, e): includes s, not e. Meetings work this way.
sort key
What you sort by: start for merging, end for greedy keeping.
sweep line
Walk sorted +1 / -1 events through time with a running count.
heap of end times
The end time of every busy room; the smallest frees up first.
greedy
Make the best-looking choice now and never undo it; safe here when you keep the earliest end.

Recap: the pattern card in one minute

Idea: sort the intervals once. Then each one only needs one comparison with the last one kept (or a running count), instead of every pair.

Signals: start and end pairs; meetings, bookings, ranges, balloons; "overlap", "merge", "rooms", "fewest to remove", "free time".

Templates: merge: sort by start, if s <= last_end stretch with max, else append. Rooms: +1 / -1 events, ends first at equal times, track the peak. Remove fewest: sort by end, keep the earliest end. Insert: before, overlapping, after.

Cost: O(n log n) for the sort, O(n) for the scan. At n = 1000: 999 scan checks plus 8,630 sort comparisons, against 499,500 pair checks.

Traps: what touching means; sorting by the wrong key (or not at all); replacing the end instead of taking the max.

In the sandbox, type your own intervals and run all three templates on them. Try touching intervals and one long interval that swallows the rest.
