Prefix Sums

Goal: store running totals once, so the sum of any stretch of an array is a single subtraction. Then add a hash map, and you can count stretches with a given sum in one pass.

1. Keep a running total, then subtract

Many problems ask the same thing again and again: "what is the sum of the numbers from position l to position r?"

The slow way adds the stretch up from scratch for every question. The fast way does one pass first, writing down the total so far at every position. After that, every question is one subtraction.

Analogy: a car's odometer. The odometer shows the total distance since the car was new. You never measure a trip with a tape. You read the odometer when you leave and when you arrive, and subtract. A 3-hour drive and a 3-minute drive cost the same: two readings and one subtraction.

Try it: four questions on the same array

The array is [3, 1, 4, 1, 5, 9, 2, 6]. The questions ask for the sums of index 1..4, 0..7, 2..5 and 3..6 (both ends included).

Slow: re-add every stretch. For each question, walk from l to r and add. One operation per number added.

Fast: odometer first. Build the running totals once (8 additions). Then each question is one subtraction.

Both counts come from running the code, here and in measure.py: 20 against 12. The answers are 11, 31, 19 and 17 either way. With 4 short questions the gap is small; the race below makes it big.

Rule to rememberprefix[i] is the sum of the first i numbers. The sum of index l..r is prefix[r + 1] - prefix[l].

4. Mental map: from a blank page to working code

Read this list top to bottom when a problem mentions sums of stretches.

  1. Signal"Sum of the elements between l and r", many such questions, "subarray sum equals k", "as many 0s as 1s", "left sum equals right sum", or many "add v to every slot from l to r" updates.
  2. Ask"Can I write the sum of any stretch as one running total minus an earlier one?" If yes, store the running totals (or a map of them) and the question becomes a lookup.
  3. PickChoose the variant by what is asked. The clue for each sits in yellow.
    • many range-sum questions, array never changesPrefix array: build once, answer with prefix[r + 1] - prefix[l]. Range Sum Query.
    • "left side equals right side"Total minus left: walk once with a running left sum; right = total - left - x. Find Pivot Index.
    • count stretches with sum k, negatives allowedPrefix count map: found += counts[prefix - k], seeded with {0: 1}. Subarray Sum Equals K.
    • "equal number of two kinds"Balance trick: +1 / -1, then the longest stretch with total 0. Keep the first index of each balance. Contiguous Array.
    • "divisible by k"Map of remainders: two equal prefix % k values mark a stretch divisible by k.
    • many range updates, read at the endDifference array: +v at l, -v at r + 1, one running total at the end.
  4. Invariantprefix[i] is the sum of nums[0..i-1]. So sum(nums[l..r]) = prefix[r + 1] - prefix[l]. In the map version: before index i is counted, the map holds every running total of the stretches that end before i, including the empty start (0).
  5. StepsSeed with 0. Loop once, updating the running total. Ask the question (subtract, or look up prefix - k). Then record the current total. Return the answer.
  6. CheckOff by one: the prefix array has n + 1 slots, and the range l..r uses r + 1.
  7. CheckDid you seed the map with {0: 1} (or {0: -1} for "first index")? Without it, stretches that start at index 0 are missed.
  8. CheckAsk before you record, or the empty stretch counts itself when k = 0.
  9. CheckNegative numbers? Then a sliding window is wrong for "sum equals k": the sum no longer only grows when the window grows.
Rule to rememberStretch sum = later total minus earlier total. Seed with 0, ask, then record.

5. Templates

Template A: build once, answer many

CodeWhat it means
def range_sums(nums, queries):Answer many "sum of l..r" questions.
  prefix = [0] * (len(nums) + 1)n + 1 slots. prefix[0] = 0 is the zero seed.
  for i in range(len(nums)):One pass over the array.
    prefix[i + 1] = prefix[i] + nums[i]The next reading = this reading + the next number.
  answers = []One answer per question.
  for l, r in queries:Each question, l and r both included.
    answers.append(prefix[r + 1] - prefix[l])Reading after r minus reading before l. O(1).
  return answersO(n + q) time, O(n) extra space.

Step through it on [3, 1, 4, 1, 5] with the questions 1..3 and 0..4.

measure.py prints prefix = [0, 3, 4, 8, 9, 14], and the sum of index 1..3 is 9 - 3 = 6.

Template B: count stretches that sum to k (prefix count map)

A stretch ending at i sums to k exactly when an earlier running total equals prefix - k. So count how often each running total has appeared, and look up prefix - k.

CodeWhat it means
def count_sum_k(nums, k):How many subarrays sum to exactly k?
  counts = {0: 1}The zero seed: the empty start has total 0, seen once.
  prefix = 0The running total so far.
  found = 0The answer counter.
  for x in nums:One pass.
    prefix += xUpdate the reading.
    found += counts.get(prefix - k, 0)Ask first: how many earlier readings are exactly k below this one? Each is a stretch ending here.
    counts[prefix] = counts.get(prefix, 0) + 1Then record this reading.
  return foundO(n) time, O(n) space. Works with negative numbers.

Step through nums = [1, 2, 3, -2, 2], k = 3. Watch the map of readings fill up.

From measure.py: 4 stretches found in 5 map steps. The brute force adds 15 sums to get the same 4. At n = 10,000 it is 10,000 map steps against 50,005,000 sums.

Template C: the balance trick (+1 / -1)

"As many 0s as 1s" becomes "the stretch sums to 0" if a 1 counts +1 and a 0 counts -1. Two equal balances mark such a stretch. For the longest one, remember the first index of each balance.

CodeWhat it means
def longest_balanced(bits):Longest stretch with equal 0s and 1s.
  first = {0: -1}Balance 0 is "seen" just before index 0.
  balance = 0Running +1 / -1 total.
  best = 0Longest length so far.
  for i, b in enumerate(bits):One pass.
    balance += 1 if b == 1 else -1A 1 steps up, a 0 steps down.
    if balance in first:Seen this balance before?
      best = max(best, i - first[balance])Then everything after that index, up to i, is balanced.
    else:New balance:
      first[balance] = irecord its first index only.
  return bestO(n) time, O(n) space.

From measure.py: [0, 1, 1, 0, 1, 1, 1, 0] gives 4 (index 0..3), the same as the brute force.

Template D: two more shapes

Total minus left (pivot) 
total, left = sum(nums), 0
for i, x in enumerate(nums):
    if left == total - left - x:
        return i
    left += x
return -1

No array needed: the right side is total - left - x. On [2, 3, -1, 8, 4] it returns 3: left 4, right 4.

Difference array (updates) 
diff = [0] * (n + 1)
for l, r, v in updates:
    diff[l] += v
    diff[r + 1] -= v
# one running total of diff = final values

Updates (1..3, +2), (2..5, +3), (0..1, +1) on 6 zeros give [1, 3, 5, 5, 3, 3].

Rule to rememberArray of totals for range questions. Map of totals for "how many" or "how long" questions. Same seed of 0 in both.
Pattern words

6. Spot the pattern: running totals or not?

Decide yes or no, and name the variant. Then reveal.

A. A fitness app stores the steps you walked each day for a year. It must answer thousands of "how many steps between day a and day b?" questions.

Yes: prefix array. Fixed data, many range-sum questions. Build once, then prefix[b + 1] - prefix[a].

B. A bank account log has deposits (positive) and withdrawals (negative). Count the stretches of back-to-back entries whose total is exactly zero.

Yes: prefix count map with k = 0. Every repeated running balance marks a zero-sum stretch. Negative numbers rule out a sliding window.

C. A football match log lists each goal as "home" or "away". Find the longest stretch of goals where both teams scored equally often.

Yes: balance trick. home = +1, away = -1, keep the first index of each balance, longest gap wins.

D. All numbers are positive. Find the shortest stretch whose sum is at least 50.

Not this pattern (look-alike). "At least", and only positive numbers: growing the stretch only raises its sum. That is a sliding window: O(n) with O(1) memory, no map needed.

E. A list of prices; find two prices (anywhere, not neighbours) that add up to 100.

Not this pattern (look-alike). It says "sum", but the two items are not a stretch of neighbours. That is a complement lookup in a hash map (Two Sum).

F. A concert hall gets 10,000 bookings, each "seats l to r, add 2 people". After all bookings, report how many people sit in each seat.

Yes: difference array. Each booking is two writes, diff[l] += 2 and diff[r + 1] -= 2; one running total at the end gives every seat.

Trigger signalsSums of contiguous stretches, asked many times; "sum equals k" with negatives; equal counts of two kinds; left versus right totals; many range updates. Not: positive-only "at least / at most" (window), or pairs anywhere (hash map).

7. Classic traps

Trap 1: off by one 
prefix = [0, 3, 4, 8, 9, 14]       # nums = [3, 1, 4, 1, 5]
prefix[3] - prefix[1]   # 5: wrong, misses nums[3]
prefix[4] - prefix[1]   # 6: right, index 1..3 = 1 + 4 + 1

Fix: say it out loud: "reading after r, minus reading before l": prefix[r + 1] - prefix[l].

Trap 2: no zero seed in the map 
counts = {}                 # should be {0: 1}

On [1, 2, 3] with k = 3, the stretch [1, 2] starts at index 0. Its earlier reading is the empty start, 0, which was never stored. measure.py: buggy 1, right 2. Fix: counts = {0: 1}.

Trap 3: recording before asking 
counts[prefix] = counts.get(prefix, 0) + 1   # recorded first ...
found += counts.get(prefix - k, 0)            # ... so with k = 0 it finds itself

On [1, 2] with k = 0 the right answer is 0, but this counts 2: each reading matches itself, an empty stretch. Fix: ask, then record.

Trap 4: a sliding window when numbers can be negative

A window shrinks while its sum is too big. That only works if adding a number never lowers the sum. On [1, -1, 0] with k = 0, the window finds 1 stretch; the right answer is 3 ([1, -1], [1, -1, 0], [0]). On all-positive [1, 2, 3], k = 3, both say 2. Fix: any negative numbers, use the prefix count map.

Trap 5: keeping the last index in the balance trick 
first[balance] = i          # overwrites the earlier index every time

For the longest stretch you need the earliest start. On [0, 1, 1, 0, 1, 1, 1, 0] this returns 2 instead of 4. Fix: only store a balance the first time you see it.

Rule to rememberr + 1. Seed with 0. Ask, then record. Negatives mean map, not window. First index for "longest".
Maths

8. Complexity: count it, then name it

Step 1: re-adding vs prefix for q questions

Re-adding a whole-array question costs n additions, so q questions cost q x n. Prefix sums cost n additions to build and 1 subtraction per question: n + q.

n = q = 1000: 1,000,000 against 2,000 (500 times fewer)

Big-O: O(q x n) against O(n + q). Extra space: O(n) for the prefix array.

Step 2: counting stretches, brute force vs map

An array of n numbers has n x (n + 1) / 2 stretches. The brute force adds each one up incrementally: 15 sums for n = 5, 50,005,000 for n = 10,000.

The map version does one step per number: n steps, each with a dict lookup and a dict update, O(1) on average. So O(n) time and up to n + 1 map entries: O(n) space.

Step 3: why it cannot be faster, and the hidden costs

Every number can change the answer, so any correct method must read all n of them: O(n) is the floor. Hidden costs to watch: sum(nums[l:r + 1]) inside a loop looks like one line but is O(n) per call, and Python's itertools.accumulate(nums, initial=0) builds the prefix array in one line, still O(n).

10. Your lesson's questions

Q1. Build the prefix array of [2, -1, 3, 5]. What is the sum of index 1..3?

prefix = [0, 2, 1, 4, 9]. Sum of 1..3 = prefix[4] - prefix[1] = 9 - 2 = 7 (-1 + 3 + 5). From measure.py.

Q2. How many subarrays of [1, 1, 1] sum to 2?

2: index 0..1 and index 1..2. The readings are 1, 2, 3; at 2 the map has 0 once, at 3 it has 1 once. Run it in the sandbox to watch.

Q3. What is the longest balanced stretch of [0, 0, 1, 0, 1, 1]?

6, the whole array: three 0s and three 1s. The balance returns to 0 at index 5, and 0 was first seen at -1, so 5 - (-1) = 6. Brute force agrees in measure.py.

Recap: the pattern card in one minute

Idea: like an odometer, store running totals once; the sum of any stretch is a later reading minus an earlier one.

Signals: many range-sum questions; "subarray sum equals k" (especially with negatives); equal counts of two kinds; left total versus right total; many range updates.

Templates: prefix[i + 1] = prefix[i] + nums[i], then prefix[r + 1] - prefix[l]. Counting: counts = {0: 1}; found += counts.get(prefix - k, 0); then record. Longest: first = {0: -1}, keep first index only.

Cost: O(n) to build, O(1) per question; the map version is O(n) time and space. At n = q = 1000: 2,000 operations against 1,000,000.

Traps: r + 1; the zero seed; ask before recording; negatives rule out a window; first index, not last.

In the sandbox, type your own array and k, and watch the map of readings. Try one with negative numbers and one with zeros.
