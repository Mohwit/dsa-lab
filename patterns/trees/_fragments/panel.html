1. Ask the left, ask the right, combine

A tree is a set of boxes joined by arrows. One box sits at the top. Every box points down to at most two smaller boxes.

The trick: a box below you is the top of its own smaller tree. So a question about the whole tree splits into the same question about two smaller trees.

Analogy: a company org chart. The CEO wants to know how many layers deep the company is. She does not walk every corridor. She asks her two direct reports: "how deep is your team?" Each of them asks their own two reports, and so on. A person with no reports answers "just me: 1". Every manager takes the bigger answer from below, adds 1 for themselves, and reports up.

Before you press play: the tree below has 9 people. How many layers deep is it? And how many people must be asked at least once?

4 layers, and all 9 people are asked exactly once. Every answer travels up one arrow, so nobody is asked twice.

Try it: the same tree, two ways

The tree in level order is [8, 3, 10, 1, 6, null, 14, null, null, 4, 7, 13]. Lit circle: the person being asked. Orange ring: a manager waiting for an answer. Faded: finished.

Pattern: ask the reports. Each person asks left, then right, then reports 1 + the bigger answer. Watch the call stack grow and shrink.

Slow: walk every path. Start at the top and walk down to each person with no reports, one path at a time. Shared bosses get walked again and again.

ask the reports- node visits
walk every path- node visits

Both counts come from running the two methods on this tree, in the page and in measure.py (9 visits against 15). The gap grows with the tree: the diameter race in section 4 shows a 512x gap.

Rule to rememberTrust the recursive call. Assume f(node.left) already returns the right answer for the left subtree. Your only job is the base case and the combine step.

3. Mental map: from a blank page to working code

Read this when a new tree problem lands and you do not know where to start.

  1. SignalThe input is a root. Words like depth, height, path, level, ancestor, subtree, "validate" or "build the tree".
  2. Ask"If my two children already gave me their answers, could I build mine?" If yes, it is DFS. If the question says "level", "row" or "closest to the top", it is BFS.
  3. Pick the variantFive shapes cover nearly every problem:
    • answer = f(left, right)Return-a-value DFS. Max depth, same tree, invert, balanced.
    • a rule from above: bounds, best so farCarry state down as arguments. Validate BST, count good nodes, path sum.
    • "longest / largest path anywhere"Global answer: return a height, update a best on the side. Diameter, max path sum.
    • "each level", "right side", "fewest steps"BFS with a queue, one level per loop.
    • BST and "kth smallest" or "in order"Inorder walk visits values sorted. Or go left or right by comparing.
  4. InvariantA call on a node returns the correct answer for that node's subtree, and nothing else. The global answer, if any, lives outside the return value.
  5. Steps1. Write the base case for None. 2. Call left and right. 3. Combine. 4. Decide what flows down (arguments) and what flows up (return value). 5. Test on an empty tree, one node and a long chain.
  6. CheckDid you handle None before touching .val? Is the return value the same kind of thing at every node? For a BST, did you pass the bounds down, not just compare with the parent? Could the tree be a chain 104 deep (recursion limit)?

4. Templates: one per variant

Every template uses this node class. Trees on this page come in LeetCode's level-order format, with null for a missing child.

class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val, self.left, self.right = val, left, right

Template A: return a value (combine the children)

CodeWhat it means
def max_depth(node):Answer for the subtree that starts at node.
if not node:Base case first: an empty spot.
return 0An empty tree has depth 0. This is what a leaf's children say.
left = max_depth(node.left)Ask the left report. Trust the answer.
right = max_depth(node.right)Ask the right report.
return 1 + max(left, right)Combine: me plus the deeper side. This is postorder: the work happens after both children.

Same shape, different combine: same tree compares a.val == b.val and same(a.left, b.left) and same(a.right, b.right); invert swaps the two answers; count nodes returns 1 + left + right.

Template B: carry state down (validate a BST)

Sometimes a node cannot decide alone. It needs a rule from above, such as "every value here must be between 5 and 8". Pass that rule down as arguments.

CodeWhat it means
def is_bst(node, lo, hi):lo and hi are the bounds every ancestor has set so far. Start with minus and plus infinity.
if not node: return TrueAn empty tree breaks no rule.
if not lo < node.val < hi:Check this node against the bounds from all its ancestors, not just its parent.
return FalseOne broken rule anywhere is enough.
if not is_bst(node.left, lo, node.val):Going left: the ceiling drops to my value. A failure on the left stops the search.
return is_bst(node.right, node.val, hi)Going right: the floor rises to my value.

Count good nodes (1448) is the same move: pass down the biggest value seen on the path so far.

Template C: return one thing, record another (diameter)

The longest path between any two nodes may not pass through the root. So each node answers two different questions: "how tall am I?" for its parent, and "how long is the best path bending at me?" for the global answer.

CodeWhat it means
best = 0The global answer lives outside the recursion.
def height(node):Returns a height. Never the diameter.
nonlocal bestLets the helper write to best (or use self.best, or a one-item list).
if not node: return 0Empty: height 0.
l = height(node.left)
r = height(node.right)		Heights of the two arms.
best = max(best, l + r)A path that bends here uses both arms: l + r edges. Record it on the side.
return 1 + max(l, r)Tell the parent my height. A path going up can only use one arm.

The tree below is [1, 2, null, 3, 4, 5, null, null, 6]. Its longest path bends at 2, not at the root. Watch best change at node 2.

Template D: BFS, one level per loop

CodeWhat it means
q = deque([root])A queue: first in, first out. It holds the next nodes to visit. (Return [] first if root is None.)
while q:One loop turn per level.
for _ in range(len(q)):Freeze the level size now. Children added during the loop belong to the next level.
node = q.popleft()Take from the front. list.pop(0) would cost O(n) each time.

Template E: the order you visit in (BST gives sorted)

Where you put the "handle this node" line decides the order. In a BST, inorder (left, me, right) visits values smallest first. That is why "kth smallest in a BST" is an inorder walk that stops at step k.

The player starts on preorder. Predict the inorder order of the picture tree before you press Inorder.

1, 3, 4, 6, 7, 8, 10, 13, 14: sorted, because the tree is a BST. So the 3rd smallest is 4. Preorder is 8, 3, 1, 6, 4, 7, 10, 14, 13 and postorder is 1, 4, 7, 6, 3, 13, 14, 10, 8 (all printed by measure.py).

Rule to rememberDecide two things before coding: what flows down (arguments) and what flows up (the return value). If the answer is not what flows up, keep it in a variable outside.

Pattern words

5. Spot the pattern: which tree move, if any?

Read each made-up task. Decide: is it a tree problem, and which variant? Then reveal.

A. A family tree with one founder. Count the people who are older than every ancestor above them.

Tree, carry state down. A node cannot decide alone; it needs "the oldest so far on my path". Pass it as an argument. This is Count Good Nodes in a costume.

B. A building's floors form a tree of rooms. From the side, which room do you see on each floor if you stand on the right?

Tree, BFS by level. Signal: "each floor" means each level. Keep the last node of each level. (A DFS that visits right first and records the first node per depth also works.)

C. In a tree of cities connected by roads, find the two cities farthest apart (most roads between them).

Tree, global answer. The longest path may bend anywhere. Return a height, update best = max(best, l + r) on the side. This is the diameter.

D. Office IDs are stored in a BST. Find the 5th smallest ID.

Tree, BST inorder. Inorder visits a BST in sorted order. Count as you go and stop at 5.

E. A list of friendships between 50 people, where friend groups can form loops. Is everyone connected?

Not this pattern. Loops and "a list of pairs" mean a graph: no root, no left and right, and you need a visited set or you walk in circles. That is the Graphs pattern. A tree never has a loop.

F. A sorted array of prices. Find whether 42 is in it, in O(log n) time.

Not this pattern. It smells like a BST ("go left if smaller"), but the input is a sorted array. Binary search on indexes does it with no tree at all.

G. Given two trees, decide whether the second appears somewhere inside the first, with the same shape and values.

Tree, return a value, twice. A "same tree" DFS that returns True or False, called from a second DFS over every node of the big tree. This is Subtree of Another Tree.

Trigger signalsA root is given; depth, height, path, level, ancestor, subtree, "validate" or "build". No root and possible loops means graph, not tree.

6. Five classic traps

Trap 1: no base case for None

The code reaches a leaf, calls itself on the empty child, and then reads .left of nothing.

def depth(node):
    return 1 + max(depth(node.left), depth(node.right))   # no base case

# measure.py, on [1, 2]:
AttributeError: 'NoneType' object has no attribute 'left'

Fix: start every tree function with if not node: return <base>. Also check node.left is not None before reading node.left.val.

Trap 2: only measuring through the root

For the diameter, it is tempting to return height(root.left) + height(root.right). That misses paths that bend lower down.

# measure.py, tree [1, 2, null, 3, 4, 5, null, null, 6]:
root-only diameter: 3     # wrong
one-pass diameter:  4     # the path 5-3-2-4-6 bends at node 2

Fix: record l + r at every node in a best outside the recursion, and return the height (Template C). The same trap hits Max Path Sum (124), where the return value also drops negative arms: max(0, ...).

Trap 3: checking a BST against the parent only 
if node.left and node.left.val >= node.val: return False
if node.right and node.right.val <= node.val: return False

# measure.py, tree [5, 4, 6, null, null, 3, 7]:
buggy local check: True    # 3 < 6 is fine locally, but 3 sits right of 5
bounds check:      False

Fix: pass lo and hi down (Template B). Use strict < when duplicates are not allowed, and real infinities, not 0 or a magic number.

Trap 4: BFS without freezing the level size

If you drop the for _ in range(len(q)) line, the queue never tells you where one level ends.

# measure.py, picture tree, levels without the size snapshot:
[[8, 3, 10, 1, 6, 14, 4, 7, 13]]
# with it:
[[8], [3, 10], [1, 6, 14], [4, 7, 13]]

Fix: read len(q) once at the top of each level, before you add any children.

Trap 5: a very deep tree and Python's recursion limit 
# measure.py, a left-only chain of 5000 nodes:
recursive depth (default limit 1000) -> RecursionError: maximum recursion depth exceeded
BFS level count -> 5000

Fix: LeetCode trees are usually under 104 nodes, and many judges raise the limit. Say it out loud in an interview, and offer an iterative version (BFS, or DFS with your own stack) if the tree can be a long chain.

Maths

7. Complexity: count the visits

Step 1: every node is visited once, every empty spot once

A tree with n nodes has n + 1 empty child spots. Template A calls itself once per node and once per empty spot.

calls = n real + (n + 1) empty = 2n + 1

measure.py on a perfect tree of 15 nodes: 15 real visits and 16 empty calls, 31 in all. Each call does O(1) work, so the time is O(n).

Step 2: memory is the height, not the size

DFS keeps one call per level on the call stack, so it needs O(h) memory, where h is the height. Same 15 nodes, two shapes:

perfect tree: h = 4     long chain: h = 15

BFS keeps a whole level in the queue. The widest level of the perfect 15-node tree holds 8 nodes; the chain's widest level holds 1. So BFS costs O(w), the width. For a balanced tree, h is about log2 n and w is about n / 2.

Step 3: the hidden cost of recomputing heights

The naive diameter calls height() at every node. On a long chain, the node with s nodes below it pays s - 1 more visits:

n + (0 + 1 + ... + (n - 1)) = n(n + 1) / 2

For n = 1000 that is 500,500 visits against 1,000. For n = 100,000 it is 5,000,050,000 against 100,000. That is O(n2) against O(n), and why interviewers ask for the one-pass version.

Check yourself

9. Your lesson's questions

Q1. Template A runs on [1, null, 2, null, 3] (a chain leaning right). What does it return, and how many calls hit None?

Depth 3, with 4 empty calls (3 real nodes, so 3 + 1 empty spots). measure.py prints (3, 3, 4). Try it in the sandbox.

Q2. What are the levels of [1, 2, 3, 4, null, null, 5], and what is its right side view?

Levels [[1], [2, 3], [4, 5]], right side view [1, 3, 5]. Note that 4 hangs under 2 and 5 under 3, so they are on the same level even though they are far apart.

Q3. Is [10, 5, 15, null, null, 6, 20] a valid BST? What does the parent-only check say?

Not valid: 6 sits in the right subtree of 10 but is smaller than 10. The parent-only check says True (6 < 15 is fine locally). The bounds check says False, because 6 arrives with lo = 10.

Glossary: new words from this lesson

binary tree
Nodes where each one has at most a left and a right child.
node, root, leaf
A box with a value; the top box; a box with no children.
subtree
A node and everything below it.
depth / height
How far down a node is / the most nodes on any root-to-leaf path.
base case
The input a recursive function answers without calling itself. For trees, None.
DFS
Depth-first search: finish one branch before the next, usually with recursion.
BFS
Breadth-first search: level by level, with a queue.
preorder, inorder, postorder
Handle the node before, between or after its children.
BST
Left subtree smaller, right subtree larger, at every node. Inorder visits it sorted.
call stack
Calls still waiting for an answer. Its height is the recursion depth: O(h) memory.
queue, deque
First in, first out. collections.deque pops from the front in O(1).
diameter
The most edges on a path between any two nodes.
nonlocal
Lets an inner function write to a variable of the function around it.

Recap: the pattern card in one minute

Idea: a tree question splits into the same question on the left and right subtrees. Base case for None, ask both children, combine.

Signals: a root is given; depth, height, path, level, ancestor, subtree, validate, build. Loops or "list of pairs" mean a graph instead.

Templates: A return a value (1 + max(l, r)); B carry state down (BST bounds, best so far); C return a height, record a global best (diameter); D BFS with for _ in range(len(q)); E inorder of a BST is sorted.

Cost: O(n) time, O(h) stack for DFS or O(w) queue for BFS. Recomputing a helper at every node is O(n2) on a chain: 523,776 against 1,023 visits at n = 1023.

Traps: no None base case; returning the global answer instead of the height; BST checked against the parent only; BFS without the level size; deep chains and the recursion limit.

In the sandbox, type your own tree in level order and run max depth or level order. Try a long chain, then a perfect tree, and compare the stack height with the queue width.
