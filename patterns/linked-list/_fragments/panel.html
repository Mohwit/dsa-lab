Linked List

Goal: stop thinking of a list as boxes in a row. A linked list is a chain of nodes, each holding one arrow to the next. You will learn to re-point arrows safely, and to send two walkers down the chain at different speeds.

1. Move the arrows, not the items

An array keeps its items side by side, so a[3] is one jump. A linked list does not. Each item lives in a node, and each node only knows where the next one is.

Analogy: a treasure hunt. The first clue is taped to the front door. It says "look under the mat". Under the mat, the next clue says "look in the shed". You cannot jump to clue 4; you must follow clues 1, 2 and 3. But changing the route is cheap: rewrite one clue and the hunt takes a new path, without moving a single box.

That gives the two big rules of this pattern. Getting to a node costs a walk. Changing the shape of the list costs only a few arrow changes, with O(1) extra memory.

Try it: reverse the hunt, two ways

The list is 1 → 2 → 3 → 4 → 5. Press Step or Play on each player and watch the counter of hops.

Pattern: flip each arrow once. Walk the list one time. At each node, turn its arrow round to point back. The circles under and over the nodes are the pointers prev, cur and nxt.

Slow: walk to the end, again and again. You cannot step backwards in a chain. So to take the last node, this way walks from the head every round. Blue nodes are already in the new list.

walk to the end- hops

Both counts come from running the two methods on this list, in the page and in measure.py (5 hops and 10 hops). Section 7 lets you grow the list and race them.

Rule to rememberIn a linked list you never move values around. You walk with a few pointers and re-point arrows. Every arrow change is O(1).

3. Mental map: from a blank page to working code

Read this top to bottom when a linked list problem lands in front of you. It is the "how do I start" checklist.

  1. SignalThe input is a ListNode. The task says reverse, merge, reorder, remove, find the middle, find the k-th from the end, or "is there a loop?". Or it asks for O(1) extra memory on a chain.
  2. Ask"Can I get there by walking once with a few pointers, and changing arrows as I go?" Then: "Could the head itself change?" and "Do I need to know where the end is before I reach it?"
  3. PickChoose the variant by its clue in yellow. Many problems chain two or three of them.
    • reverse, palindrome, reorderIn-place reversal with prev, cur, nxt. Reverse Linked List, Reorder List, Reverse Nodes in k-Group.
    • the head may changeDummy head: build or edit after a fake node, return dummy.next. Merge Two Sorted Lists, Remove Nth Node, Add Two Numbers.
    • middle, loop, "repeats in 1..n"Fast and slow pointers. Linked List Cycle, the middle step of Reorder List, Find the Duplicate Number.
    • "k-th from the end", one passGap pointers: give fast a head start of k nodes, then move both until fast runs off. Remove Nth Node From End.
    • extra links, or O(1) lookups by keyHash map of nodes next to the list: old node to new node for a deep copy, key to node for a cache. Copy List with Random Pointer, LRU Cache.
  4. InvariantFor reversal: everything up to prev is already reversed, and cur onwards is untouched. For fast and slow: after r rounds, slow has walked r nodes and fast 2r.
  5. StepsDraw three or four boxes with arrows on paper. Name every pointer. For each loop round, write the moves in order and check no node becomes unreachable. Decide the loop condition from what the last move touches (cur, or fast and fast.next). Return the right head.
  6. CheckDid you save cur.next before you overwrote it? If not, the rest of the list is gone (Trap 1).
  7. CheckEvery x.next needs x to be a node. With two hops, test fast and fast.next (Trap 2).
  8. CheckEdge lists: empty (head is None), one node, two nodes, removing the head, and an odd vs even length.
Rule to rememberDraw it before you code it. Three boxes and some arrows catch nearly every linked list bug.

4. Four templates cover most of this pattern

Template A: reverse in place

CodeWhat it means
def reverse(head):Turn every arrow round; return the new head.
prev, cur = None, headNothing is reversed yet, so prev is None. The old head will become the tail, pointing at None.
while cur:One round per node, until cur walks off the end.
nxt = cur.nextSave the rest of the list. The next line destroys this arrow.
cur.next = prevFlip: this node now points back.
prev = curThe reversed part grows by one node.
cur = nxtStep forward using the saved arrow.
return prevWhen cur is None, prev stands on the old tail, which is the new head.

Template C: fast and slow pointers

Fast moves two nodes per round, slow moves one. When fast falls off the end, slow is in the middle. If there is a loop, fast can never fall off; it comes round from behind and lands on slow. This is Floyd's algorithm, also called the tortoise and the hare.

CodeWhat it means
slow = fast = headBoth walkers start at the head.
while fast and fast.next:Fast is about to read fast.next.next, so both fast and fast.next must be real nodes.
slow = slow.nextOne step.
fast = fast.next.nextTwo steps.
if slow is fast: return True(Loop check only.) Compare the nodes with is, not their values: two nodes can hold the same value.
return slow / FalseMiddle: slow. Loop check: fast found the end, so no loop.

Where does the loop start? After they meet, put one pointer back at the head and move both one step at a time. They meet again at the loop's first node. The real output from measure.py:

Why the restart-from-head trick finds the loop's start

Say the path from the head to the loop's start is a nodes, and they meet b nodes into the loop, where the loop has c nodes. Slow walked a + b. Fast walked twice that, and the extra distance is whole laps: 2(a + b) - (a + b) = k x c for some whole k.

a + b = k x c, so a = k x c - b

From the meeting point, walking a more nodes means walking k laps minus b, which lands exactly on the loop's start. A pointer from the head reaches the start after the same a steps. In the example, a = 2 and they meet on node 5; both then reach node 3 together.

Template D: gap pointers (remove the n-th node from the end)

CodeWhat it means
dummy = ListNode(0, head)The node to remove might be the head, so stand before it.
fast = slow = dummyBoth start on the dummy.
for _ in range(n + 1): fast = fast.nextGive fast a head start of n + 1 nodes.
while fast: fast, slow = fast.next, slow.nextWalk both until fast is None. The gap never changes.
slow.next = slow.next.nextslow stands just before the target; skip over it.
return dummy.nextThe head, which may be a new one.
 
remove_nth([1, 2, 3, 4, 5], 2) = [1, 2, 3, 5]
remove_nth([1, 2], 2)          -> [2]        # removing the head: fine with a dummy
Rule to rememberReverse with prev, cur, nxt. Use a dummy whenever the head can change. Use two speeds for the middle or a loop, and a head start for "from the end".

5. Spot the pattern: which linked list trick fits?

Read each made-up task. Decide: is it this pattern, and which variant? Then reveal.

A. A playlist is a chain of songs. Play it in the opposite order, without making a copy.

Yes: in-place reversal. Signal: reverse, plus "no copy". Template A, O(n) time and O(1) memory.

B. A train of carriages is a chain. Uncouple the carriage that is third from the back, walking the train only once.

Yes: gap pointers plus a dummy. Signal: "k-th from the end" in one pass. Give fast a head start; the dummy covers the case where the third from the back is the engine.

C. You are given a chain of nodes and nothing else. Does following the arrows ever bring you back to a node you visited?

Yes: fast and slow. Signal: a possible loop. A set of visited nodes also works, but uses O(n) memory; Floyd uses O(1).

D. A Python list of numbers must be reversed in place.

No, not this pattern. It says "reverse", but the input is an array: you can jump to any index. Swap a[i] and a[j] from both ends (two pointers). There are no arrows to re-point.

E. A web browser keeps the pages you visited so the back button can return to the last one.

No, not this pattern. "Return to the most recent one" is last in, first out: a stack (a Python list with append and pop). A linked list could store it, but none of the linked list tricks are needed.

F. Start from a number, replace it by the sum of the squares of its digits, and repeat. Does it reach 1, or loop for ever?

Yes, in disguise: fast and slow. There is no ListNode, but "next value" works like a next pointer. Run slow with one step and fast with two; they meet if the numbers loop. This is LeetCode 202, Happy Number.

Trigger signalsA ListNode input; reverse, merge, reorder or remove; middle or k-th from the end; "is there a loop?"; O(1) extra memory. Any "follow the next value" process, even without nodes, can use fast and slow.

6. Four classic traps

Trap 1: cutting before you save next

Flip the arrow first and the only route to the rest of the list is gone. Step through it: after the flip, cur = cur.next follows the new arrow, back to None.

# == 4. Traps ==
reverse_buggy([1, 2, 3]) = [1]   # nodes 2 and 3 are lost
reverse([1, 2, 3])       = [3, 2, 1]

Fix: nxt = cur.next is always the first line inside the loop.

Trap 2: half a null check

This middle-finder tests only fast.next. On an even-length list, fast lands on None, and the next test reads None.next.

while fast.next:             # wrong
    slow = slow.next
    fast = fast.next.next

middle_buggy([1, 2, 3, 4]) -> AttributeError: 'NoneType' object has no attribute 'next'
middle([1, 2, 3, 4])       -> 3

Fix: while fast and fast.next:. Before every x.next, ask "can x be None here?"

Trap 3: no dummy when the head can go

Removing the 2nd node from the end of [1, 2] means removing the head. Without a dummy, fast runs off the list during its head start and the loop test crashes.

fast = slow = head                 # wrong: no node before the head
for _ in range(n): fast = fast.next
while fast.next: ...

remove_nth_no_dummy([1, 2], 2) -> AttributeError: 'NoneType' object has no attribute 'next'
remove_nth([1, 2], 2)          -> [2]

Fix: start both pointers on dummy = ListNode(0, head) and return dummy.next.

Trap 4: the hidden cost of recursive reversal

Reversing with recursion is short and pretty, but each node waits on the call stack. That is O(n) memory, and Python stops at about 1000 levels.

recursion limit = 1000
reverse_recursive(1200 nodes) -> RecursionError: maximum recursion depth exceeded
reverse(1200 nodes) -> 1200 nodes, no crash

Fix: in Python, use the loop (Template A) unless the list is known to be short. Say the O(n) stack cost out loud if you do recurse.

Rule to rememberSave next, then cut. Check every pointer before you read its .next. A dummy whenever the head can change.

Step 1: where 10 and 499500 come from

Round one walks from the head to the last node: n - 1 hops. Round two: n - 2. The last round: 0.

(n - 1) + (n - 2) + ... + 1 + 0 = n x (n - 1) / 2

For n = 5 that is 5 x 4 / 2 = 10, the count you saw in section 1. For n = 1000 it is 499500. That is O(n2). The pattern does one hop per node: O(n).

Step 3: why fast and slow meet within one lap

Once both are inside the loop, fast gains exactly one node on slow every round. The gap from fast round to slow is less than the loop length c, so it shrinks to 0 in fewer than c rounds. Slow walks less than one lap after entering. In the example (2 nodes before a loop of 4) they meet after 4 rounds.

9. Your lesson's questions

Q1. Template A runs on 7 → 8. How many times does cur.next = prev run, and what does node 7 point to at the end?

2 times, once per node, and node 7 points to None: it is the new tail. measure.py prints 2 hops for [7, 8].

Q2. The middle-finder (Template C) runs on 1 → 2 → 3 → 4. Which node does it return?

3, the second of the two middles. Round 1: slow to 2, fast to 3. Round 2: slow to 3, fast to None. If a problem wants the first middle (as Reorder List's split does), start fast at head.next.

Q3. Remove the 1st node from the end of the one-node list [5]. What should come back, and why does the dummy matter?

An empty list (None). The node to remove is the head. With the dummy, slow stays on the dummy and dummy.next becomes None. measure.py prints remove_nth([5], 1) = [].

Recap: the pattern card in one minute

Idea: each node knows only the next one. Walk with a few named pointers and re-point arrows; never move values. Every arrow change is O(1).

Signals: a ListNode input; reverse, merge, reorder, remove; the middle or k-th from the end; "is there a loop?"; O(1) extra memory.

Templates: reverse with four moves in order: nxt = cur.next, cur.next = prev, prev = cur, cur = nxt. A dummy when the head can change. slow 1 step and fast 2 steps while fast and fast.next. A head start of n for "from the end".

Cost: O(n) time, O(1) extra memory. Walking to the end every round is O(n2): 499,500 hops against 1000 at n = 1000.

Traps: cutting before saving next; reading .next on None; no dummy when the head goes; recursion's O(n) stack.

In the sandbox, type your own chain and reverse it, find its middle, or give it a loop with pos and watch fast catch slow.
