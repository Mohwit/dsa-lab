1. Make a choice, go deeper, undo it on the way back

Some problems ask for every answer: every group, every order, every way to split. There is no clever formula. You have to build the answers.

Backtracking builds them one choice at a time. When a choice leads nowhere, you step back and try the next one.

Analogy: walking a maze with chalk. At each fork you pick a tunnel and draw a chalk line behind you. At a dead end you walk back to the last fork, rubbing the chalk out as you go. Then you try the next tunnel. The chalk line is always exactly the route from the entrance to where you stand.

Here is a small job. From the numbers [2, 3, 4, 5], pick some (each at most once) that add up to 7.

Every set of picks is a decision tree node. The slow way visits every node and tests it. The pattern way walks the same tree but cuts a branch the moment it is too big.

Try it: the same tree, two ways

Press Step or Play on each player. Teal is where you are, a ring marks an answer, and a faded node is a branch that was cut without being walked.

Slow: build every subset, then test it. It walks all 16 nodes, even after the sum has passed 7.

Pattern: backtrack with pruning. The numbers are sorted. As soon as the next number is bigger than what is left, stop that loop.

A node visited is one call of the helper bt. Both players find the same two answers, [2, 5] and [3, 4]. measure.py prints 16 nodes for the slow way and 9 nodes with 4 cuts for the pattern way.

Rule to rememberChoose, explore, un-choose. And the moment a partial answer cannot possibly work, do not go any deeper.

Take the numbers 1, 2, 3, ... n and a target T. Find every set of different numbers that adds up to T. The slow racer builds every subset. The fast racer cuts a branch as soon as the next number is too big.

Look at T = 10. Going from n = 10 to n = 20 doubles the slow count ten times over, but the pruned count stays at 43. The numbers above 10 are cut at the very first test, so they cost almost nothing.

Rule to rememberPruning does not change the worst case, but it decides whether your search finishes. Sort first when you can, so one failed test lets you break instead of continue.

4. Mental map: from a blank page to working code

Read this when a new problem looks like it might be backtracking.

  1. SignalThe task says "all", "every", "list each", or "generate". Or it is a puzzle with rules (queens, sudoku, words on a board). And n is small: about 20 or less for groups, about 10 or less for orders.
  2. Ask"Can I build one answer by making one choice at a time? What are the choices at each step? When is a half-built answer already hopeless?"
  3. PickWhich kind of choice is it?
    • any size, order does not matterSubsets: start index, record at every node.
    • pick to a target or a size kCombinations: start index, record only when complete. Reuse allowed means bt(i), else bt(i + 1).
    • every order or arrangementPermutations: a used set, every unused item may come next.
    • a path on a grid or boardBoard search: mark the cell, explore the neighbours, unmark it.
    • cut a string into piecesPartition: the choice is where the next piece ends.
    • repeated items in the inputAny of the above plus: sort first, then skip an equal item at the same level.
  4. Invariantpath holds exactly the choices from the root to the current node. When bt returns, path (and used, and the board) is exactly as it was before the call.
  5. Steps1. Base case: if the path is complete, save path[:] and return. 2. Loop over the choices. 3. Skip or break on choices that cannot work. 4. Choose, call bt, un-choose.
  6. CheckDid you save a copy? Does every append have a pop? Do duplicates in the input give duplicate answers? Is the next start i or i + 1? Does the empty input work?
Not backtrackingIf the task wants only a count or a best value, and the same smaller question keeps coming back, it is dynamic programming. If it wants the shortest route on a grid, it is breadth-first search.

5. Three templates, one shape

All three share the same skeleton: a helper bt, a shared path, a base case, and a loop of choose, explore, un-choose. Only the choice rule changes.

Template A: subsets (start index, every node is an answer)

CodeWhat it means
def subsets(nums):Return every group of the numbers, of any size.
out, path = [], []All answers, and the chalk line.
def bt(start):The helper. start is the first index we may still pick.
out.append(path[:])Every node is a subset, so save a copy right away.
for i in range(start, len(nums)):The choices: only items after the last one picked. That stops [2, 1] after [1, 2].
path.append(nums[i])Choose.
bt(i + 1)Explore. The next pick must come after i.
path.pop()Un-choose: the path is back to what it was.
bt(0); return outStart at the root with an empty path.

Template B: permutations (used set, record when full)

CodeWhat it means
used = [False] * len(nums)Which items are on the path right now.
if len(path) == len(nums):Base case: every item is placed.
out.append(path[:]); returnSave a copy and go back up.
for i in range(len(nums)):Any item may come next, from the start: order matters.
if used[i]: continueAlready placed: skip it.
used[i] = True; path.append(nums[i])Choose: mark and add.
bt()Explore the next seat.
path.pop(); used[i] = FalseUn-choose both things you changed.

Template C: combinations to a target (start index, prune, reuse)

CodeWhat it means
cands = sorted(cands)Sorting is what makes the break below safe.
def bt(start, remain):remain is how much of the target is still missing.
if remain == 0: out.append(path[:]); returnBase case: the target is hit exactly.
for i in range(start, len(cands)):Choices from start on, so each group comes out in one order only.
if cands[i] > remain: breakPrune. This one is too big, and every later one is bigger.
path.append(cands[i])Choose.
bt(i, remain - cands[i])Explore. i, not i + 1: the same number may be used again. Use i + 1 when each may be used once.
path.pop()Un-choose.

Pattern words

6. Spot the pattern: is this backtracking?

Read each made-up task. Decide yes or no, name the variant, and name the clue. Then reveal.

A. Four friends go to the cinema. List every way they can sit in a row of four seats.

Yes: permutations. Clue: "every way", and order matters (who sits where). Use a used set. There are 4! = 24 answers.

B. A bakery has trays of different weights. List every set of trays (each used at most once) that fills a van to exactly 20 kg.

Yes: combinations to a target. Clue: "every set" that hits a total, order does not matter. Start index with bt(i + 1), sort, and break when a tray is heavier than what is left.

C. How many different ways can you climb 30 steps if each move is 1 or 2 steps?

No, not this pattern. It asks for a count, not the list. Backtracking would walk every single way, and their number grows like the Fibonacci numbers. The same question ("ways from step k") repeats, so it is 1D dynamic programming: one loop.

D. A grid of letters is printed on a card. Can a given word be traced through side-by-side cells without using a cell twice?

Yes: board search. Clue: a path with a "no reuse" rule. Mark the cell, try the four neighbours, unmark it on the way back. Prune as soon as a letter does not match.

E. A robot is in a maze of walls. Find the fewest moves from the entrance to the exit.

No, not this pattern. It looks like the chalk maze, but it asks for the shortest route, not every route. Backtracking would try path after path. Breadth-first search finds the shortest one by exploring in rings (a later pattern).

F. Cut a word into pieces so that every piece reads the same forwards and backwards. List every way to cut it.

Yes: partition. Clue: "list every way to cut". The choice at each step is where the next piece ends. Prune any piece that is not a palindrome before going deeper.

G. Each digit on an old phone stands for three or four letters. List every word a digit string could spell.

Yes: one choice per position. Depth = position in the digit string, choices = that digit's letters. Nothing to prune; the answer count is the product of the letter counts. Watch the empty input.

Trigger signals"All", "every", "list each", "generate"; puzzles with rules; small n. Count or best value only: think dynamic programming. Shortest: think breadth-first search.

7. Four classic traps

Trap 1: saving the path, not a copy

out.append(path) saves the same list object every time. The search keeps changing it and leaves it empty at the end, so every saved answer is empty.

# == 4. Traps ==
no copy  subsets([1, 2, 3]) = [[], [], [], [], [], [], [], []]

Fix: out.append(path[:]) (or list(path)).

Trap 2: forgetting to un-choose

Without path.pop() the chalk is never rubbed out. Each new branch starts from the old branch's leftovers.

no pop   subsets([1, 2, 3]) = [[], [1], [1, 2], [1, 2, 3], [1, 2, 3, 3], [1, 2, 3, 3, 2], [1, 2, 3, 3, 2, 3], [1, 2, 3, 3, 2, 3, 3]]

Fix: every change before the call is undone after it. In permutations that is two lines: path.pop() and used[i] = False. On a board, unmark the cell.

Trap 3: repeated items give repeated answers

With [1, 2, 2] the two 2s look different to the loop, so [1, 2] and [2] appear twice.

plain subsets([1, 2, 2]) = [[], [1], [1, 2], [1, 2, 2], [1, 2], [2], [2, 2], [2]]  (8 lists)
sort + skip  ([1, 2, 2]) = [[], [1], [1, 2], [1, 2, 2], [2], [2, 2]]  (6 lists)

Fix: sort, then in the loop if i > start and nums[i] == nums[i - 1]: continue. It skips an equal number at the same level only, so [1, 2, 2] is still allowed. Using a set of tuples at the end also works, but it builds every duplicate first.

Trap 4: the wrong next start

In combination sum, restarting the loop at 0 on every level lets the same group come out in several orders.

restart at 0: combination_sum([2, 3, 5], 8) = [[2, 2, 2, 2], [2, 3, 3], [3, 2, 3], [3, 3, 2], [3, 5], [5, 3]]
start at i  : combination_sum([2, 3, 5], 8) = [[2, 2, 2, 2], [2, 3, 3], [3, 5]]

Fix: pass the start index down. bt(i, ...) when a number may be reused, bt(i + 1, ...) when each is used once.

Rule to rememberCopy when you save. Undo everything you changed. Sort and skip for repeated items. Decide i or i + 1 on purpose.
Maths

8. What it costs, and why n must be small

Backtracking is a brute force with good manners. The number of answers itself is huge, so the cost is huge too.

# == 5. Growth: answers and tree nodes ==
n =  3: subsets 2^n =         8  permutations n! =             6  permutation tree nodes =            16
n =  4: subsets 2^n =        16  permutations n! =            24  permutation tree nodes =            65
n =  5: subsets 2^n =        32  permutations n! =           120  permutation tree nodes =           326
n =  8: subsets 2^n =       256  permutations n! =        40,320  permutation tree nodes =       109,601
n = 10: subsets 2^n =     1,024  permutations n! =     3,628,800  permutation tree nodes =     9,864,101
n = 12: subsets 2^n =     4,096  permutations n! =   479,001,600  permutation tree nodes = 1,302,061,345
n = 20: subsets 2^n = 1,048,576  permutations n! = 2,432,902,008,176,640,000  permutation tree nodes = 6,613,313,319,248,080,001
Step 1: subsets cost O(n x 2n)

Each number is either in or out: 2 x 2 x ... x 2 = 2n subsets, and the tree has exactly one node per subset (checked by running it for n = 3 to 6).

Saving each one copies up to n items. For n = 10, measure.py counts 1,024 subsets and 5,120 items copied in total, which is n x 2n / 2. So the time is O(n x 2n).

Step 2: permutations cost O(n x n!)

n choices for the first seat, n - 1 for the second, and so on: n! orders. The tree has a bit more than that in nodes (65 for n = 4, against 24 answers), and each answer is a copy of n items.

nodes = 1 + n + n(n-1) + ... + n! (about e x n! for big n)
Step 3: memory

Not counting the output, the extra memory is the path plus the open calls: O(n). The recursion is at most n deep, far below Python's default limit of about 1000.

The output itself can be huge: all subsets of 20 numbers hold over a million lists.

Step 4: what the limit on n tells you

About a million nodes is fine in an interview. 220 is 1,048,576, so subsets work up to n = 20. 10! is 3,628,800, but 12! is already 479,001,600, so permutations stop around n = 10. If a problem allows n = 105, it is not backtracking.

Pruning helps a lot in practice (24,385 times fewer nodes in the race), but the worst case Big-O stays the same.

10. Your lesson's questions

Q1. Template A runs on [1, 2, 3, 4]. How many times is bt called?

16 times, one per subset: 24 = 16. measure.py prints subsets([1, 2, 3, 4]) nodes = 16.

Q2. Template B runs on [1, 2, 3, 4]. How many answers, and how many nodes?

24 answers and 65 nodes. 1 root + 4 + 4 x 3 + 4 x 3 x 2 + 24 = 65. The sandbox shows the same counts.

Q3. The sort-and-skip subsets runs on [2, 1, 2]. What does it return?

[[], [1], [1, 2], [1, 2, 2], [2], [2, 2]]. Sorting gives [1, 2, 2] first, so the order of the input does not matter. Six lists, no repeats.

Q4. Combination sum with candidates [3, 5] and target 4. How many nodes, and what is the answer?

2 nodes, no answers: []. The root picks 3 (remain 1), and at that node 3 > 1 cuts at once. Back at the root, 5 > 4 cuts too. measure.py prints 2 nodes and 2 cuts.

Glossary: new words from this lesson

backtracking
Building answers one choice at a time, undoing the last choice to try the next one.
decision tree
All possible choices drawn as a tree. The root is "nothing chosen", each step down adds a choice.
path
The choices made so far, from the root to the current node.
choose / explore / un-choose
Append a choice, recurse, then pop the same choice.
base case
The test that says the path is complete: save a copy and return.
prune
Stop exploring a branch because no answer can be below it.
start index
Where the next choices begin. Keeps each group in one order only.
used set
Marks which items are on the path; used for permutations.
copy
path[:]: a new list with the same items, safe to keep.
leaf
A node with no children.
recursion depth
How many calls are open at once; at most n in these templates.
brute force
Trying every candidate. Backtracking is a brute force that drops hopeless candidates early.

Recap: the pattern card in one minute

Idea: build answers one choice at a time on a shared path. Choose, explore, un-choose. Cut any branch that cannot work.

Signals: "all", "every", "generate", "list each"; rule puzzles (queens, word on a board); small n (about 20 for groups, about 10 for orders).

Template: a helper bt(start). Base case: out.append(path[:]) and return. Then for each choice i from start: path.append(x), bt(i + 1), path.pop(). Start index for groups, used set for orders, sort and break to prune.

Cost: O(n x 2n) for subsets, O(n x n!) for permutations, O(n) extra space plus the output. In the race, pruning visited 43 nodes instead of 1,048,576.

Traps: saving path instead of path[:]; a missing pop; duplicates (sort and skip at the same level); i versus i + 1.
