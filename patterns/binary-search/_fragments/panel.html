Binary Search

Goal: whenever one question tells you which half holds the answer, throw the other half away. You will play it as a game, learn three templates that cover almost every problem, and learn to spot the traps that make binary search famous for bugs.

1. Throw away half, every time

If one question can tell you which half holds the answer, you never need to look at the other half. Ask about the middle, keep the half that can still hold the answer, and repeat.

Each question halves what is left. So the work grows with the number of halvings, not with the size of the input.

Analogy: higher or lower. A friend thinks of a number from 1 to 100. You guess, and they say "higher" or "lower". Guess 50 first, and one answer rules out half the numbers. Keep guessing the middle of what is left, and you never need more than 7 guesses.

Play it: find my number

Type a guess and press Guess. The blue cells are still possible; grey ones are ruled out. Try it your way first. Then play again using Guess the middle.

Pattern: binary search. Look at the middle. Too small? Drop the left half. Too big? Drop the right half.

Slow: linear scan. Check the items one by one from the left until you hit the target.

Counted by running both, in the page and in measure.py: 4 probes against 12 checks. A probe is one look at a middle item.

The target is bigger than every item, the worst case for both. Pick a size and start the race.

Rule to rememberBinary search needs one thing: a yes/no question whose answers line up as all "no" then all "yes" (or the other way round). Sorted data gives you that question for free.

3. Mental map: from a problem statement to binary search

Read this when a problem might be binary search but you are not sure what to search over.

  1. SignalSorted input. "O(log n)" in the statement. "The minimum X such that ..." or "the maximum X that still ...". Answers in a huge range (up to 109) with a quick way to test one candidate. A sorted list that was rotated.
  2. AskIs there a yes/no question that is "no" for a while, then "yes" forever? If I ask it at the middle, do I know which half to throw away?
  3. Pick the variantEach variant has a tell-tale signal:
    • sorted, find this exact valueTemplate A: exact match, lo <= hi, return as soon as you hit it.
    • first / last position, insert pointTemplate B: lower bound, the first index where the test turns true.
    • minimum speed, size, days that worksTemplate C: search on the answer with feasible(x).
    • sorted but rotatedCompare with the last item (minimum), or check which half is sorted (search).
    • sorted grid, rows follow onTreat it as one list: row = i // cols, col = i % cols.
  4. InvariantWrite it down before the code: "if the answer exists, it is in lo..hi" (Template A) or "the first true is in lo..hi" (Templates B and C). Every update must keep it true.
  5. StepsSet lo and hi to cover every possible answer. Loop while the range is not empty. Take mid. Ask the question. Move lo past mid or hi onto (or past) mid. Return what the invariant promises.
  6. CheckDoes every round shrink the range? Test a range of two items. Is hi a real index or one past the end? Do <= or < in the loop match how you move hi? For rotated input, test a two-item list.

4. Three templates (and a rotated twist)

Template A: find an exact value

CodeWhat it means
lo, hi = 0, len(nums) - 1Both ends are real indices. The answer, if any, is in lo..hi.
while lo <= hi:Keep going while at least one item is left. <= because lo == hi is still one item.
mid = (lo + hi) // 2The middle, rounded down.
if nums[mid] == target: return midLucky hit: stop.
if nums[mid] < target: lo = mid + 1mid and everything left of it is too small. Drop them.
else: hi = mid - 1mid and everything right of it is too big. Drop them.
return -1lo passed hi: nothing is left, so the target is missing.

From measure.py: target 40 takes 4 probes to prove it is missing; the linear scan needs all 12 checks.

Template B: the first index where a test turns true

Most binary search problems are secretly this one. Picture the test as a row of answers: False False False True True. You want the first True.

CodeWhat it means
lo, hi = 0, len(nums)hi is one past the end. If no item passes, the answer is len(nums).
while lo < hi:Stop when lo and hi meet: that spot is the answer. Strict <.
mid = (lo + hi) // 2Rounded down, so mid is always less than hi. That is what keeps hi = mid safe.
if nums[mid] >= target:The test. Swap in any monotonic yes/no question.
hi = midTrue: mid could be the first true one, so keep it.
else: lo = mid + 1False: mid and everything left of it are false. Drop them.
return lolo == hi: the first true index.

On [1, 3, 3, 3, 5, 8, 9], measure.py prints index 1 for target 3, index 4 for target 4, and 7 (the length) for target 10, each in 3 probes. Last position of 3 = lower_bound(4) - 1 = 3.

Template C: search on the answer

A story: boxes hold 4, 9, 5 and 12 letters. You sort at a steady speed of k letters per hour, one box at a time, and any time left over in an hour is wasted. What is the slowest speed that finishes within 7 hours?

There is no sorted list here. But the yes/no question "is speed k fast enough?" is no, no, ..., yes, yes as k grows. So binary search the speed.

Slide k and watch the yes/no row: once a speed works, every faster speed works too. That shape is what makes binary search legal here.

The rotated twist

A sorted list cut once and swapped round, like [6, 7, 9, 1, 2, 4, 5]. Two tricks cover it.

Finding the smallest item is Template B with a clever test: "is nums[i] at most the last item?" The left piece answers no, the right piece answers yes. The first yes is the smallest item.

Finding a target: around any mid, at least one half is sorted. Find it, then ask whether the target sits inside that sorted half.

CodeWhat it means
if nums[lo] <= nums[mid]:The left half lo..mid is sorted. Use <=: when lo == mid, that half is a single item.
if nums[lo] <= target < nums[mid]: hi = mid - 1The target fits inside the sorted left half: go left.
else: lo = mid + 1Otherwise it can only be on the right.
else: (the right half mid..hi is sorted)Same idea, mirrored.
if nums[mid] < target <= nums[hi]: lo = mid + 1Inside the sorted right half: go right.
else: hi = mid - 1Otherwise go left.

From measure.py: the smallest item of [6, 7, 9, 1, 2, 4, 5] is at index 3 (3 probes); target 2 is at index 4, target 7 at index 1, target 3 is missing (-1).

Rule to rememberFind the yes/no question first. Then pick Template A for "is it exactly here?" and Template B for "where does the answer start?". Search on the answer is Template B over candidate answers.
Pattern words

5. Spot the pattern: binary search or not?

Read each made-up task. Decide if binary search fits, and which template. Then reveal.

A. An app has versions 1 to n. Some version broke the login, and every version after it is broken too. You can test one version at a time. Find the first broken one.

Yes, Template B. "Is version v broken?" is no, no, ..., yes, yes. Find the first yes.

B. Parcels must leave in the given order over D days. Find the smallest truck capacity that ships them all in time.

Yes, search on the answer. Signal: "smallest capacity that works". feasible(c) packs the parcels greedily day by day. lo = the heaviest parcel, hi = the total weight.

C. A shuffled list of IDs. Does ID 4721 appear in it?

No. The list is not sorted, so the middle tells you nothing about which half to keep. One question: a linear scan, O(n). Many questions: a set. Sorting first costs O(n log n), worth it only for many searches.

D. Without any square root function, find the whole-number part of the square root of x (x up to 231).

Yes, search on the answer. "Is k x k > x?" is no, then yes. The answer is the first yes minus one (the last k with k x k <= x).

E. A sorted list of prices. Find two prices that add up to exactly 100.

Not the best fit. It is sorted, so binary searching each partner works in O(n log n). But two pointers, one at each end, does it in O(n). Sorted input is a signal for both patterns; "a pair" points to two pointers.

F. A list was sorted, then cut and swapped round, like a clock starting at 9. Find where the original first item ended up.

Yes, the rotated variant. The original first item is the smallest. Template B with the test "nums[i] <= nums[-1]".

G. Find the longest stretch of a string with no repeated letter.

No: sliding window. You could binary search the length (if length L works, so does L - 1), but each check costs O(n), giving O(n log n). A window that grows and shrinks does it in one O(n) pass.

Trigger signalsSorted data, "O(log n)", "minimum or maximum value that works", a huge answer range with a quick check, rotated sorted lists. Not for unsorted lookups (hash set) or sorted pairs (two pointers).

6. Classic traps

Binary search is short, and famous for bugs anyway. A bug of this kind even sat for years inside Java's own library search. Here are the ones that bite in interviews, each run on a real input.

Trap 1: lo = mid with a mid that rounds down

Looking for the last item <= target, it is tempting to write lo = mid. With two items left, (lo + hi) // 2 equals lo, so lo never moves.

mid = (lo + hi) // 2       # wrong with lo = mid
mid = (lo + hi + 1) // 2   # fixed: round up when the "keep" move is lo = mid

# measure.py on [1, 3], target 5
round-down mid: after 1000 rounds lo = 0, hi = 1 (stuck)
round-up mid:   1 round, answer index 1
Trap 2: hi one too far

Template A needs hi = len(nums) - 1. With hi = len(nums) and lo <= hi, a target bigger than everything walks mid off the end.

# measure.py on [1, 3, 5], target 9
hi = len(nums)     -> IndexError: list index out of range
hi = len(nums) - 1 -> -1
Trap 3: mixing the two templates

while lo <= hi belongs with hi = mid - 1. while lo < hi belongs with hi = mid. Mix them and, once lo == hi on a true item, nothing changes.

# measure.py on [1, 3, 5], target 3: "lo <= hi" with "hi = mid"
after 1000 rounds lo = 1, hi = 1 (stuck)
"lo < hi" with "hi = mid" -> index 1 in 2 probes
Trap 4: which half is sorted, with two items

In a rotated search, writing nums[lo] < nums[mid] instead of <= breaks when lo == mid: a one-item left half counts as "not sorted", so the code trusts the wrong half.

# measure.py on [3, 1], target 1
nums[lo] <  nums[mid] -> -1   # wrong: 1 is right there
nums[lo] <= nums[mid] -> 1
Trap 5: a search range that includes an impossible answer

In search on the answer, lo = 0 lets mid become 0, and feasible(0) divides by zero.

# measure.py on piles [1, 1], h = 5
lo = 0 -> ZeroDivisionError: integer division or modulo by zero
lo = 1 -> 1

In Java or C++, also watch (lo + hi) / 2: the sum can overflow. Write lo + (hi - lo) / 2. Python integers never overflow.

Rule to rememberEvery round must shrink the range. Test by hand on one item, two items, and a target off each end.
Maths

7. Why halving is so fast

Step 1: count the probes

Each probe keeps at most half of what was left. Start with n items. After one probe at most n / 2 are left, after two n / 4, and so on until none are left. The number of probes is about log2 n, plus one.

# measure.py: worst-case probes (target bigger than everything)
n = 10: 4      n = 100: 7      n = 1000: 10
n = 1,000,000: 20      n = 1,000,000,000: 30      n = 10^18: 60
doubling n: 1 -> 1, 2 -> 2, 4 -> 3, 8 -> 4, 16 -> 5, 32 -> 6

Doubling the list adds just one probe. A thousand times more items adds about ten.

Step 2: search on the answer

The binary search makes about log2 M calls to feasible, where M is the size of the answer range. Each call here walks all n boxes. Total: O(n log M).

Each call doubles the precision, so a range of about 109 speeds takes about 30 calls (measure.py counts 29 and 30 on its two big examples). With n boxes that is about 30 x n steps, where trying every speed from 1 upward could take up to 109 x n.

Step 3: memory and hidden costs

The loop uses O(1) extra memory: just lo, hi and mid. A recursive version that passes slices like nums[mid + 1:] copies half the list each time, which costs O(n) in total and hides the log n speed. Pass indices, not slices.

Sorting first costs O(n log n). That is only worth it if you then search many times.

Costs at a glanceTemplates A and B: O(log n) time, O(1) space. Search on the answer: O(cost of feasible x log M). A 2D matrix of r x c: O(log(r x c)).

9. Your lesson's questions

Q1. A sorted list has 1000 items. What is the most probes Template A can ever need?

10. 210 = 1024 is the first power of two above 1000. measure.py tries every target from -1 to 1000 and the maximum is 10.

Q2. What does lower_bound([1, 3, 3, 5, 8], 4) return?

3. The first value that is at least 4 is the 5 at index 3. It is also where 4 would be inserted to keep the list sorted. measure.py: 3 probes.

Q3. Boxes of 3, 8 and 6 letters, 6 hours allowed. What is the slowest speed that works, and which speeds does Template C try?

Speed 3; it tries 4, 2, then 3. Hours at speeds 1 to 8 are 17, 9, 6, 5, 5, 4, 4, 3. lo = 1, hi = 8: mid 4 works (hi = 4), mid 2 needs 9 hours (lo = 3), mid 3 needs 6 hours and works (hi = 3). Check it in the sandbox.

Glossary: new words from this lesson

binary search
Repeatedly ask about the middle and throw away the half that cannot hold the answer.
probe
One look at a middle item; one round of the loop.
search space, lo, hi, mid
Where the answer could still be, its two ends, and the middle (rounded down).
invariant
A promise true before and after every round, such as "the answer is in lo..hi".
monotonic predicate
A yes/no test that is false, then true from some point on, and never switches back.
lower bound
First index with value >= target. Python: bisect.bisect_left.
search on the answer
Binary search over candidate answers using feasible(x).
feasible(x)
Says whether answer x works; must be monotonic in x.
rotated sorted array
A sorted list cut once and swapped round; one half around any mid is still sorted.
log n
How many halvings take n down to 1: about 10 for 1000, 20 for a million.

Recap: the pattern card in one minute

Idea: if one question tells you which half holds the answer, throw the other half away. n items need about log2 n probes: 10 for 1000, 20 for a million.

Signals: sorted input, "O(log n)", "minimum or maximum value that works", a huge answer range with a quick check, rotated sorted lists.

Template A: lo, hi = 0, n - 1; while lo <= hi; move to mid + 1 or mid - 1. Template B: lo, hi = 0, n; while lo < hi; hi = mid on true, lo = mid + 1 on false; return lo. Template C: Template B over answers with feasible(x).

Cost: O(log n) time, O(1) space. Search on the answer: O(cost of feasible x log of the range).

Traps: lo = mid with a round-down mid; hi one past the end with <=; mixing templates; < instead of <= in rotated halves; an impossible value (like speed 0) inside the range.

In the sandbox, try all three templates on your own input. Give the exact-match mode an unsorted list to see why sorting matters.
