Advanced Graphs: Shortest Paths and MST

Goal: when edges have weights, find the cheapest route from one node to all others (Dijkstra, Bellman-Ford), and the cheapest way to connect every node (Prim, Kruskal). You will see why plain BFS gives wrong answers here, and which small greedy rule makes each method correct.

1. The nearest unfinished town is already settled

In the Graphs lesson every edge cost the same, so "fewest edges" meant "shortest". Now each road has its own length. Two short roads can beat one long road.

We want the cheapest cost from one start node to every other node. Trying every route works, but the number of routes explodes. One greedy rule fixes it.

Analogy: water spreading through pipes. Pour water in at town A. Every pipe has a length, and water flows at the same speed in all of them. The water reaches towns one by one, nearest first. The moment water first arrives at a town, that arrival time is the shortest distance: any other route is still on its way. Dijkstra simulates this, always jumping to the next town the water would reach.

The graph below has six towns. The small circles on the roads are the lengths. Start at A.

Try it: the same graph, two ways

Slow: try every path. Walk every route from A that never repeats a town, and keep the cheapest cost seen for each town. The teal edges show the route being tried.

Fast: Dijkstra. Keep a heap of (cost, town). Always take the cheapest one; that town is now final. Then offer its roads to its neighbours.

Dijkstra- edge checks

Both counts come from running the two methods on this graph (in the page and in measure.py, which prints 128 edge checks over 42 paths, against 18). Both find the same answers: A=0, B=3, C=1, D=8, E=10, F=12. Dijkstra looks at each road once from each end, so 9 roads give 18 checks.

Why not plain BFS?

BFS goes out in rings and keeps the first cost it finds for each node. With weights, the first route found is the one with the fewest roads, not the cheapest. Step through it and watch B get 4, although A to C to B costs 1 + 2 = 3.

measure.py prints BFS: B=4, D=9, E=11, F=13. Four of the five answers are wrong.

The second idea: connect everything as cheaply as possible

A different question uses the same graph: pick roads so every town is connected, with the smallest total length. You do not care how long any single trip is; you pay for the roads you build.

Analogy: laying cable between villages. Split the villages into any two groups. Some cable must cross between the groups, and the cheapest crossing cable is always a safe choice. Prim grows one group outward, always buying the cheapest cable that leaves it. Kruskal buys cables from cheapest up, skipping any that joins two villages already connected.
Rule to rememberShortest paths: the cheapest unfinished node in the heap is final (only true when no weight is negative). Spanning tree: the cheapest edge crossing any split is safe.

3. Mental map: from the problem statement to code

  1. SignalNodes joined by edges that carry a number: time, price, distance, effort, probability. Words like "cheapest", "minimum time", "least cost to connect", "within k stops".
  2. AskAm I finding the best route from a start (a path), or choosing edges so everything is connected (a tree)? Then: can a weight be negative, and is the number of edges capped?
  3. PickEach variant has a tell-tale signal:
    • one start, weights 0 or moreDijkstra with a min-heap. Network Delay Time.
    • negative weights, or at most k edgesBellman-Ford: k + 1 rounds, read last round, write a copy.
    • connect all, least totalMST. Prim for a dense graph (all point pairs), Kruskal for an edge list.
    • path cost = its worst stepBottleneck: Dijkstra with max instead of plus, or binary search on the limit plus BFS.
    • every edge costs the sameNot this lesson: plain BFS from the Graphs lesson.
  4. InvariantDijkstra: every popped, non-stale node is final, and dist holds the cheapest cost found so far for the rest. Bellman-Ford: after round r, cost holds the best price using at most r edges. MST: the edges kept so far are part of some cheapest tree.
  5. StepsBuild an adjacency list graph[u] = [(v, w), ...]. Push the start. Loop: pop the cheapest, skip it if stale, mark it final, relax each edge and push any improvement. Read the answer from dist (largest value, one target, or -1 if a node is missing).
  6. CheckDirected or undirected (add both directions)? Nodes numbered from 0 or 1? Unreachable nodes (return -1)? A negative weight (not Dijkstra)? A cap on stops (copy the array each round)? Stale entries skipped?

Template B: Bellman-Ford with at most k stops

A flight with k stops uses k + 1 flights. Round r finds the cheapest price using at most r flights, so k + 1 rounds give the answer. Each round must read the old costs, or one round could chain several flights.

CodeWhat it means

for _ in range(k + 1):One round per allowed flight.
new = dict(cost)Write into a copy. Read from last round.
for a, b, w in flights:Look at every flight once per round.
if cost[a] + w < new[b]: new[b] = cost[a] + wRelax using the old cost of a: one more flight, no more.
cost = newThe round is over; its costs become "last round".

Without a stop limit, Bellman-Ford runs n - 1 rounds: a shortest path never needs more than n - 1 edges. If a further round still improves something, the graph has a negative cycle.

The bottleneck variantWhen a path costs its worst single step (Swim in Rising Water, Path With Minimum Effort), keep Template A and change one line: nd = max(d, w) instead of d + w. The greedy rule still holds, because taking one more step never makes the worst step smaller.
Pattern words

5. Spot the pattern: which tool, if any?

Read each made-up task. Name the method and the clue. Then reveal.

A. A courier leaves the depot. Roads list travel minutes. Report the fastest time to reach each house.

Dijkstra. One start, cheapest cost to all, minutes are never negative.

B. A robot moves in a maze of open and blocked cells. Every move costs one step. Find the fewest moves to the exit.

Not this pattern: plain BFS. Every move costs the same, so fewest edges is cheapest. Dijkstra would also work, but it adds a heap and a log factor for nothing.

C. A company wants every office on one network. Linking two offices has a known price. Spend as little as possible in total.

MST. "Connect all" plus "least total". Kruskal on the list of links, or Prim.

D. Train tickets between cities have prices. You may change trains at most twice. Find the cheapest trip.

Bellman-Ford with a cap. Two changes means at most three tickets: three rounds, each reading last round's costs.

E. A hiker crosses a height map. A route is as hard as its steepest single step. Find the easiest route from corner to corner.

Bottleneck Dijkstra. The cost is the worst step, so use max(d, w) instead of d + w. Binary search on the allowed step plus BFS also works.

F. Courses list which other courses must come first. Give an order to take them all.

Not this pattern: topological sort. There are no weights and nothing to minimise, only "before" rules. See the Graphs lesson.

G. Currency trades have rates. Taking logs turns them into costs, some below zero. Is there a loop of trades that makes money forever?

Bellman-Ford. Negative weights rule out Dijkstra. Run n - 1 rounds; if round n still improves a cost, a negative cycle exists.

Trigger signalsWeights on edges plus "cheapest", "fastest", "least total", "within k". Equal weights send you back to BFS; "before" rules with no weights send you to topological sort.

6. Six classic traps

Trap 1: plain BFS on a weighted graph

BFS keeps the first cost it finds, which comes from the route with the fewest edges.

if v not in dist:            # first visit wins, never improved
    dist[v] = dist[u] + w

On the lesson graph from A, BFS gives B=4, D=9, E=11, F=13. The real answers are B=3, D=8, E=10, F=12 (A to C to B costs 1 + 2 = 3). Fix: a min-heap and relaxation, so a cheaper route can replace an earlier one.

Trap 2: Dijkstra with a negative edge

Directed edges S to A 2, S to B 3, B to A -2, A to C 1. The true cheapest S to C is 3 - 2 + 1 = 2.

# == 5. Trap: a negative edge ==
dijkstra     : A=1, B=3, C=3, S=0
bellman-ford : A=1, B=3, C=2, S=0

A is popped at cost 2 and marked final, so it offers C at 3. Later B finds A at 1, but A is already done, so its roads are never offered again: C stays at 3. Fix: with any negative weight, use Bellman-Ford.

Trap 3: treating a node as final when it is pushed 
if v not in dist:            # first offer wins
    dist[v] = d + w
    heapq.heappush(heap, (d + w, v))

On the lesson graph this gives B=4, D=9, E=11, F=13, the same wrong answers as BFS. B is offered 4 by A before C (cost 1) is even popped. Fix: a node is final when it is popped, not when it is first offered. Always compare nd < dist[v].

Trap 4: not skipping stale entries

Without if u in done: continue, an old offer for a final node scans its roads again. The answers stay correct, but the work grows:

# == 3. Trap: stale heap entries (lesson graph, source A) ==
with skip    : edge checks = 18   pops = 9   stale = 3
without skip : edge checks = 28   same answer = True   extra = 10

On a dense graph the extra scans can add up to far more. Fix: skip a popped node that is already done (or whose d > dist[u]).

Trap 5: Bellman-Ford with a stop cap but no copy 
for a, b, w in flights:
    if cost[a] + w < cost[b]:    # reads values written this same round
        cost[b] = cost[a] + w

With k = 1 on the flights example, the first round already chains A to B to C to D, and the answer comes out as 3. The right answer with one stop is 5 (A to B to D). Fix: new = dict(cost), read cost, write new. Plain Dijkstra also returns 3 here, because it ignores the cap.

Trap 6: thinking the MST gives shortest paths

The MST minimises the total of all edges, not any single trip. On the lesson graph:

shortest path tree from A: total weight = 14   (uses D-F 4)
MST:                       total weight = 13   (uses E-F 3 instead)
A to F inside the MST = 13   real shortest A to F = 12

Fix: "cheapest trip" means Dijkstra; "cheapest network" means MST. Read which one the question asks for.

Rule to rememberWeights mean a heap, not a queue. Final on pop, not on push. Skip stale pops. No negatives in Dijkstra. Copy the costs each round when stops are capped.

Step 1: counting Dijkstra's work on the lesson graph

V = 6 nodes, E = 9 roads. Each node is finalised once and scans its roads once; an undirected road is scanned from both ends, so 2 x 9 = 18 edge checks. Every improvement is one push: 9 pushes (counting the start), so 9 pops, 3 of them stale.

A push or pop on a heap of size h costs about log2 h steps. At most E + 1 entries are ever in the heap, so the total is O(E log E). Since E is below V2, log E is below 2 log V, which is why you also see O(E log V).

Step 2: how fast "every path" grows

measure.py builds complete graphs (every pair joined) with random weights 1 to 9 and counts edge checks for both methods. Both find the same distances.

Going from 8 to 9 nodes multiplies the brute count by about 9. Dijkstra grows only with the edge count: exactly 2E checks.

Step 3: Prim on 1000 points (dense graph)

With n points and every pair connected, E = n(n - 1) / 2. For n = 1000 that is 499,500 edges.

# == 8. Prim on points (like LeetCode 1584), n = 1000 random points, seed 3 ==
edges in the complete graph = n(n-1)/2 = 499500
array Prim scan steps = 1000000   heap Prim pushes = 499501   same total = True

The heap version pushes about half a million entries, each costing up to about 19 heap levels (log2 of 499,501 is about 18.9), and keeps them all in memory. The array version does exactly n x n = 1,000,000 simple scans and keeps only one array. On a dense graph O(V2) beats O(E log E).

Step 4: why the greedy choices are safe

Dijkstra. When u is popped with cost d, every other offer costs at least d. Any other route to u must leave the finished set through one of those offers, then add weights that are 0 or more. So it costs at least d. A negative edge breaks the last sentence, which is exactly Trap 2.

Cut property. Suppose a cheapest tree skips the cheapest edge e across some split. Add e: it makes a loop, and that loop crosses the split a second time through some edge f with weight at least e's. Remove f: still a tree, and no more expensive. So some cheapest tree contains e.

9. Your lesson's questions

Q1. Dijkstra on the lesson graph from A: which node is finalised third, and with what cost? Which offer for it was pushed earlier and later skipped?

B, at cost 3 (A to C to B). A offered (4, B) first; that entry is popped later and skipped as stale. The finalised order is A, C, B, D, E, F (measure.py prints ACBDEF).

Q2. Run Kruskal on the lesson graph. Which edge with weight 4 is kept, and which is skipped?

Neither. By then A, B, C are already one group (A-C 1, B-C 2), so A-B 4 is skipped; D, E, F are another group (D-E 2, E-F 3), so D-F 4 is skipped too. The next edge, B-D 5, joins the two groups. Total 13.

Q3. In the flights example, what is the cheapest A to D with k = 0 stops, and with k = 2?

9 and 3. With no stops only the direct flight counts (9). With two stops, A to B to C to D costs 1 + 1 + 1 = 3. Use the k buttons in Template B to check.

Glossary: new words from this lesson

weighted graph
A graph whose edges carry numbers: lengths, prices, times.
shortest path
The route whose weights add up to the smallest total.
relaxation
If going through u is cheaper than the best known way to v, update v.
min-heap
Hands back its smallest item first; O(log n) per push or pop. Python's heapq.
final (settled)
A node whose shortest distance can no longer change; in Dijkstra, after its first pop.
stale entry
An old heap offer for a node that is already final. Skip it when popped.
Dijkstra
Shortest paths from one source with weights 0 or more: always finalise the cheapest offer.
Bellman-Ford
Relax every edge in rounds; round r allows r edges. Handles negative weights and stop caps.
negative edge / negative cycle
A weight below zero / a loop whose total is below zero, which makes "shortest" undefined.
spanning tree / MST
Edges that connect every node with no loops (n - 1 of them) / the cheapest such tree.
cut property
The cheapest edge crossing any split of the nodes belongs to some MST.
Prim / Kruskal
Grow one tree with the cheapest edge out / add edges cheapest first, skipping loops with union-find.
union-find
Keeps groups: find names a node's group, union joins two groups.
bottleneck path
A path judged by its single worst edge; solved with Dijkstra using max instead of plus.

Recap: the pattern card in one minute

Idea: with weights, the cheapest unfinished node is final (Dijkstra), and the cheapest edge across any split is safe (Prim, Kruskal).

Signals: weighted edges plus "cheapest", "fastest", "least total to connect", "within k stops", "worst step".

Templates: Dijkstra: heap of (cost, node); pop; skip if done; mark done; relax and push. Bellman-Ford: R rounds, read cost, write new. Prim: Dijkstra's loop keyed by edge weight. Kruskal: sort edges, union-find, skip loops.

Cost: Dijkstra, Prim, Kruskal O(E log E); Bellman-Ford O(R x E); array Prim O(V2) for dense graphs. On the lesson graph: 18 edge checks against 128 for trying every path.

Traps: BFS on weights; negative edges in Dijkstra; final on push; stale entries; no copy with a stop cap; MST is not shortest paths.

In the sandbox, type your own weighted graph and run Dijkstra or Prim. Try "BFS fooled" to see a cheap three-road route beat one expensive road.
