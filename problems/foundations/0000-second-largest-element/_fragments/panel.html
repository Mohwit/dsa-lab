Plain words

1. Who wins the silver medal?

A school runs a long-jump contest. Each jump is written on a list as a whole number of centimetres. Some jumpers tie with the exact same distance.

You hand out the silver medal. It goes to the second best distance, not the second best jumper. If two jumpers tie for the best distance, they share gold, and silver goes to the next distance down. If everyone jumped the same, there is no silver: answer -1.

Analogy: a two-step podium. Walk past the jumpers one at a time. Keep only two spots: gold and silver. A new jump either takes gold (and pushes the old gold down to silver), takes silver, or walks past. You never need the rest of the ranking.

Input: a list of whole numbers called arr, never empty. Output: the second largest distinct value, or -1 when the list has fewer than two different values.

Step through the three examples. The bright cell is the largest; the boxed cell is the answer.

The limits, and what they hint at

  • The list holds up to 5,000 numbers, and there can be 100 lists per run. Sorting each list is fast enough here. But an interviewer will ask for O(n), because you only need two values, not a full ranking.
  • Numbers go from minus one billion to one billion. So -1 can be a real value in the list. Keep that in mind for the "empty" marker you choose.

New words: distinctO(n)

Your solution

Your idea in one sentence: drop the repeats with a set, sort what is left from high to low, and take index 1.

Result: it passes all 20 tests, including every page example, a single number, all equal, all negative and five random lists checked against a brute force.

Cost: O(n log n) time, because of the sort. O(n) extra space for the set and the new list.

What is good: removing repeats first is exactly what makes 10 10 10 10 10 give -1 and 7 8 8 1 4 3 give 7. Many first tries return 8 there. The len(arr) < 2 check covers "one number" and "all the same" in one line.

One improvement: you sort every value but use only the top two. Keep just those two while you walk the list once, and the cost drops to O(n) time and O(1) space. Sections 6 and 9 show how.

4. Hints, one at a time

Hint 1: how much of the ranking do you really need?

Sorting builds the full order, from first to last. Which places of that order does the answer use? What could you keep instead of the whole sorted list?

Hint 2: which tool fits?

Two plain variables, first and second, updated during one walk over the list. This is the "single pass with a few tracking variables" idea from the Big-O lesson.

Hint 3: the key step, in words

For each number x: if x is bigger than first, the old first moves down to second and x becomes first. Else, if x is strictly below first and bigger than second, x becomes second. Equal to first? Ignore it.

6. Two faster ideas

Show the pattern solution

Idea A: two passes

Pass 1 finds the largest value, top. Pass 2 finds the biggest value that is strictly below top. Each pass is a plain walk, so this is already O(n).

On the example: 5 comparisons for max, then 6 steps in the second pass. 11 steps in total.

Idea B: one pass, two tracking variables (the pattern)

The one observation: the answer only depends on the top two distinct values seen so far. So keep exactly those two, and update them as each number arrives.

The invariantAn invariant is a fact that stays true every step. Here: after looking at the first i numbers, first is their largest value and second is their largest value strictly below first (or None if there is none).

Each number is looked at once: 6 steps. Watch step 4: when 35 arrives, the old champion 12 does not vanish. It steps down to second. Forgetting that move is the classic bug.

Why None and not -1 as the "empty" marker? Because -1 can be a real value in the list. With [-5, -3] and first = second = -1 at the start, neither number ever beats -1, and the code would return -1 instead of -5.

8. Mental map: how to get here next time

Show the mental map
  1. Signal"Largest", "smallest", "second", "third": the answer is a small, fixed number of values from the list.
  2. Ask"How many values do I need to remember to answer at the end?" Here: two.
  3. PickRule out the forks that do more work than needed.
    • need the whole orderSort. O(n log n), more than we need.
    • need the top k, k largeA heap of size k.
    • simplest O(n)Two passes: max, then max below it.
    • need a fixed top 2One pass with two variables.
  4. Invariantfirst is the largest so far; second is the largest so far strictly below first.
  5. StepsBoth start as None. For each x: bigger than first, shift first down and take first. Else strictly between, take second. At the end, None becomes -1.
  6. CheckWhen first changes, the old first must move to second. [1, 5] must give 1, not -1.
  7. CheckUse x < first, not x <= first, or [8, 8] gives 8.
  8. CheckStart from None (or minus infinity), never from -1 or 0: values can be negative.

9. The code, line by line

Show the code walk
CodeWhat it means
def second_largest_element(arr):Takes the list, returns one whole number.
first = second = NoneAn empty two-step podium. None cannot be confused with a real number.
for x in arr:One walk, left to right.
if first is None or x > first:A new champion (or the very first number).
first, second = x, firstThe old champion steps down to second; x takes first. Both change at once.
elif x < first and (second is None or x > second):Strictly below the champion, and better than the current runner-up. Equal to first fails here: that is the repeat guard.
second = xNew runner-up.
return -1 if second is None else secondNobody reached second place means fewer than two distinct values.

Edge cases it handles: one number (-1), all equal (-1), the largest repeated ([7, 8, 8] gives 7), all negative, rising and falling lists, and the extremes -109 and 109.

10. Counting the work

Step 1: your sort, counted
set: n inserts = 100,000 sort: about k * log2(k) comparisons = 100,000 * 16.6 = about 1,660,000 measured: Python sorted 100,000 random values with 1,529,213 comparisons

Time O(n log n). Space O(n) for the set and the list.

Step 2: one pass, and why you cannot beat O(n)
steps: n = 100,000 (one look per number) space: 2 variables = O(1)

Why O(n) is the best possible: any number you skip could have been the largest or the second largest. So every number must be read at least once.

Follow-ups: (1) how would you find the third largest? (2) what if the numbers arrive as an endless stream?

(1) Third largest: add a third variable. A new champion shifts all three down one step; skip values equal to any of them. That is LeetCode 414. For a general k, keep a min-heap of size k: O(n log k).

(2) A stream: the one-pass version already works, because it never looks back. Keep first and second and update them as each number arrives. Sorting would need to store everything.

12. Check yourself

Predict: someone writes if x > first: first = x without moving the old first down. What does [1, 5] return?

-1, but the right answer is 1. When 5 arrives, 1 is thrown away instead of moving to second place.

Predict: what does the function return for [-1, -1, 0]? Is that answer a problem?

-1, and it is correct: -1 really is the second largest. But the caller cannot tell it apart from "no answer". In an interview, point this out and offer to return None instead.

Predict: the list is promised to be sorted from small to large. What is the fastest method?

Start at the last element (the largest) and walk left until you meet a smaller value. Usually that is one or two steps, but if the end is full of repeats it is still O(n) in the worst case.

tracking variables
A few variables that hold the best values seen so far during one walk.
invariant
A fact that stays true at every step of a loop.

Recap: the pattern in one minute

Pattern: a single pass with a few tracking variables (Big-O lesson). Keep only what the answer needs.

Trigger signals: largest, smallest, second, third; "can you do it without sorting?"

Template: first = second = None; one loop; a new champion shifts the old one down; skip ties with the champion.

Cost: sort O(n log n); two passes O(n); one pass O(n) time and O(1) space.
